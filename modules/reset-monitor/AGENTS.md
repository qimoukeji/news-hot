# 共享重置监控引擎

## 事件概述与公开展示

- 事件概述由现有独立分钟 Worker 根据有来源动作、官方状态及范围生成七语言文案，写入现有事件字段；事实版本及处理状态存 monitor_state，不新增 cron。事实版本不包含生成结果；写入前校验事实及记录版本，陈旧结果不得覆盖新编辑。单独编辑只对当前事实版本有效，后续动作变化重生成。
- 仅补齐动作或范围说明的缺失翻译不视为业务事实变化：同事务保留此前仍有效的概述绑定；已过期的绑定不得恢复。动作翻译与动作管理沿用事件在先、动作在后的加锁顺序。整包文案导入只为实际改过标题或摘要的事件绑定当前事实，原样导入或仅改动作、范围不得重新认可旧概述。
- 概述缺版本或已过期时公开中性状态标题、summary=null；无来源确认由程序表达中性状态，不作为官方事实送模型。操作说明只进内部审计，七语言公开文案不得包含人工核实、人工补录、验证逻辑或模型判断等措辞。历史此类文案公开时使用业务模板及空摘要，不按单字词删除正常业务内容。
- 操作说明的过滤独立检查标题、摘要、范围说明及每种语言；覆盖“管理员已核实”“人工校验”“Manually checked”等常见表达，同时保留人工智能、企业管理员确认领取资格等正常业务用语。一个字段不安全不能连带删除另一个字段的正常业务事实。
- 事件与动作 time 必填，只允许 BusinessTime 的 instant(at)、range(from,through)、deadline(at)，拒绝 date、unknown、null、标量字符串及展示文字。announcedResetTime 有当前有效预告时直接取预告 time，无预告才为 null。resetTime、predictedResetTime 仍为 UTC ISO 字符串或 null。时间戳保留最多九位小数秒，数据库动作 time 保持 JSONB；接口读取不补时间、不转换旧格式。
- 公开页和后台共用时间格式化，本站默认中文和北京时间，范围保留两端，截止保留之前语义。后台只提供时刻、范围和截止选择器；时区可选太平洋时间、UTC 或北京时间，输入默认北京时间；修改后重新预览。
- 公开页和后台事件列表、详情共用动作行，时间线左侧统一读取动作 publishedAt，按北京时间显示 YYYY-MM-DD HH:mm，datetime 保留原始 ISO 值；不使用 updates.time 或后台动作业务时间替代发布时间。
- 业务动作即时通知；仅生成概述时同事务更新通知基线、不另发通知。Webhook 只保存和投递当前公开契约，不兼容或转换旧格式通知；展示变化不补历史通知。

本目录是 Codex、Claude、Grok 共用的实现，不在站点清单中单独安装。领域用语见根目录 `CONTEXT.md`，接口见 `docs/reset-monitor-v2.md`。

## 目录与边界

- `definition.ts`、`contracts.ts`：无后端依赖的配置和共享类型；`backend/` 与运行配置不得进入浏览器。
- `backend/`、`api/`、`web/`：共享采集、动作、事件、人工复核、公开投影与页面；供应商格式只在 `backend/providers/` 处理。
- `migrations/`：共享表新迁移，一文件一语句；已发布迁移不改，批量转换放独立工具。
- `tests/`：通用行为、跨监控隔离及转换测试；数据库以 `_test` 或 `_ci` 结尾，只连接本地假服务。
- 账号、显示名及采集规则放 site/reset-monitors.ts，平台专属事件语义留各自模块。产品、套餐和周期不设目录、代码或默认值，新监控不复制业务实现。
- 所有读写绑定服务端监控定义，主键和外键包含 `monitor_id`；HTTP 输入不能改变监控范围。
- 临时数据和运营快照放 `.data/local-preview/`，不得提交凭据或生产快照。

后台基础页分为“事件列表”和“帖子列表”两个 tab，默认事件列表，以 kind=events/posts 查询参数切换，各自分页。列表分页整行居中，上一页和下一页为页码两侧的文字链接，不可翻页时显示灰色文字，链接保留当前筛选条件。事件筛选区保留北京时间开始日期 from、结束日期 to（包含当天）；帖子列表另提供关联状态 association=all/linked/unlinked（全部/已关联/无关联），依据动作来源关系判断，筛选后再分页，提交筛选重置页码，分页保留条件，切换 tab 保留时间范围并清除页码。事件按最新来源时间筛选和排序，卡片和动作行与公开页共用布局。卡片底部“添加动作”、每条动作一个“编辑”入口直接弹框，复用动作表单、来源选择及复核预览，允许增删来源；打开读取最新数据，不显示事件编辑或动作编辑表单上方的说明段落、输入框下方说明或复核理由输入框，预览后提交，省略的理由由服务端记录操作说明，成功保留列表条件并刷新。状态全部保留为帖子识别标签，不在每条来源下重复编辑入口。新增确认允许不选来源，但须填写明确生效时间且公开标题摘要只描述业务事实；其他新动作至少一条来源。无有效初始动作时仅可预告或确认；已有关联来源的动作移除最后来源仍提示动作删除及事件影响，不转成无来源确认。冲突必须重新读取和预览，不改变事件范围、动作顺序或帖子识别进度。事件标题保留详情入口，时间线可收起；帖子列表包含已关联与未关联帖子，按发布时间筛选和排序，帖子列表提供编辑、创建和关联管理弹框，不提供处理跳转入口。不提供独立 /posts 列表页面或“核实结果”流程。

## 数据与动作

- 人工核对通知独立于采集、模型和读者订阅，由单独分钟任务发送。异常状态成功写入的同一事务记录通知轮次；既有异常、关闭期间的异常和历史修复不补发。使用现有 monitor_state 和 settings 保存独立轮次及三平台共享的北京时间每日 5 次额度；发送前复核状态和启用轮次，明确未发起的取消释放预留，请求一旦开始则保留结果，不因后续复核或新轮次覆盖。失败、超时和中断不重试，超额或跨日永久跳过。退出异常后再次进入生成新轮次，编辑和翻译不生成轮次。真实发送入口只在 SERVERCHAN_ENABLED=true 且 integrations 的 SERVERCHAN_SENDKEY 齐全时开启，测试只使用假传输；微信只发送固定原因，后台显示脱敏的运行统计和持久结果。停用须持久作废旧待发资格。

- 正式采集返回技术执行与业务处理的独立统计，明确采集是否完整、已处理及待复核数量。站点配置的每轮分页上限按跨账号新增搜索请求合计；限额中止保存固定窗口及续页位置，不推进成功游标，下一轮继续而不重复购买已收页面。结构校验错误保留安全字段路径，不将原文或模型完整响应写入日志。
- 搜索请求失败只中止当前账号，本次不重发，其他账号继续；停机、安全阀和预算拒绝立即停止。网络结果未知的搜索页保留原回执，下一次任务以关联原回执的新请求身份补采同一页，尝试计入分页上限与预算；明确拒绝沿原回执恢复，已收到的无效响应等待人工处理。窗口及成功页进度保留，全部采集与识别完成才推进截止；此恢复规则不适用于上下文补采和模型请求。

- 仅支持当前动作三表与 v2 契约，不维护旧表转换器或运行时旧表探测。业务时间升级使用独立预览、备份、分批转换及核验工具，只有该离线工具读取历史标量时间；应用不兼容旧格式。schema 和实际数据变更另行授权，历史 SQL 不改写。后台详情复用事件时间线及动作弹框，帖子保留与人工完成复核在管理弹框内操作；旧帖子处理页面返回 404。

- 公开标题和摘要只写事件或动作内容，不混入“人工补录确认”“按管理员要求补录”、执行原因、默认取时规则等操作说明；这些信息只写入内部审计。

- 三平台独立分钟翻译任务进入站点队列白名单，事件、动作及全部识别状态的帖子在创建或编辑后自动补齐七语言；只从保存的标题、摘要、范围说明读取，不读取或翻译原帖全文。用户明确开启开发翻译时只在 worker 开模型安全阀，采集与真实推送保持关闭，不修改 .env 或绕过预算、回执。保留全部已填写语言，绑定记录版本，旧结果不得覆盖新编辑；翻译不改变帖子进度、处理原因、关联、动作时间或业务状态。取消表单不产生任务，相同完整版本不重复调用，失败版本等待人工处理；新编辑生成新版本后再判断。

- 管理员从帖子新建事件并将当前帖子关联到有效首个动作，视为完成该帖人工复核：预览明确显示识别状态与原因变化，同一事务设 processed 并清空 review_reason，保留原状态和原因审计。仅补来源、编辑已有动作或移除关联仍不改变识别状态；从事件入口创建不改来源帖状态。
- 固定范围标签（如“所有用户”“付费用户”）可用共享标准译文补齐缺失语言，仅补展示文案，不从标签推断或改写 scope.type。只在所有已有语言均与标准标签一致时补全；任意自定义资格条件或冲突文案仍须完整译文才能公开，页面读取不调用模型或写数据库。

- 事件类型未明确细分时默认额度重置 direct_reset；reset_credit 与 bonus_credit 须有明确的重置卡或一次性奖励依据。唯一可核验的关联事件优先沿用其类型。kindExplicit 只记录本帖是否明示类型，默认或继承时为 false，不仅因类型未细分而复核；仍须核验额度事件、当前帖动作依据及关联，不能把无关内容或缺上下文的短回复默认成重置。

- “选择事件”子弹框参照“选择来源帖子”的候选列表：搜索框、随视口调整且最大 28rem 的固定高度滚动列表，每页 10 条；搜索重置首页，分页只切换弹框内数据，不导航页面。上一页、页码、下一页同行居中，首尾不可翻页时显示禁用文字，空结果显示第 0 / 0 页。点击事件仍进入关联操作，已撤回事件不可选，取消不修改主弹框草稿。

- 付费自动识别按帖、按动作保存：能确定目标帖、事件类型和动作类型且模型判为实际动作时，先按模型类型和动作保存并公开，核验问题写入来源帖 review_reason 并标为 needs_attention。确认仍按现有规则形成完成状态、统计和通知；不新增公开复核状态。缺少有效完成时间使用发帖时刻；预告未知时间保持 null。证据不足的已有事件关联不写入目标事件，保留为独立事件供人工修订；独立进展或修订用已有公开状态展示，不捏造初始动作。未读出动作的格式错误按帖子隔离，不影响其他可辨认动作。离线人工识别仍按严格事实校验。不自动重跑已保存动作。
- 影响范围只保留 `scope.type` 和七语言 `scope.note`，表示简短的用户范围；unknown 表示“适用范围未明确”，不能当作所有用户。产品、套餐、额度周期和具体资格只保存在已有七语言事件摘要与动作摘要中，由模型按原帖事实识别，不维护名称、代码、目录、别名、作者默认产品或映射校验。普通补来源不改写已有事实，明确变化用有来源的新动作表达；真实冲突仍需复核。
- 事件和动作 `time` 必填，只保存 `instant`、`range`、`deadline`。预告只有日期或星期时保存该日 18:00 UTC 的 instant；只有截止日期时保存该日 18:00 UTC 的 deadline；范围缺开始时刻时，当天及之前取发帖时刻，未来日期取 08:00 UTC，缺结束时刻取 18:00 UTC，准确时刻优先。完全没有时间的预告取发帖 UTC 日期 18:00，首次处理已过点取同日 23:59，保存后不重算。解析异常取发帖 UTC 日期 18:00，保留事件动作并进入 needs_attention，不因时间问题丢弃或另挂事件。有来源 confirm 一律使用确认帖发布时间；progress 缺时间用发帖时刻，amend 缺时间用不早于发帖时刻的最近一个 10:00 UTC。详见 [时间写入规则](../../docs/reset-monitor-time-normalization.md)。

- 待人工处理时同一事务保存可辨认的模型动作、有效帖子文案、回执和复核原因，原始响应只存回执。保存仍校验原始版本和 pending 状态，过期任务不能覆盖人工文案；整帖没有可用识别结果时保留已有文案，不伪造摘要或为补文案重新购买识别。

- 帖子列表提供“关联事件/管理关联”弹框，主弹框不展示顶部帖子信息或内嵌配置表单，仅按事件分组展示当前关联、待添加及待移除动作；“关联事件”和“新建事件”与“当前关联”同行左右对齐。通过独立子弹框选择事件、已有动作或填写新事件和动作，固定当前帖子为来源；子弹框确定只暂存，可组合多项新增与移除并逐项撤销，不发请求。主弹框底部提供取消和预览影响，预览后改为保存；草稿变化使预览失效，一次版本校验及事务提交全部变更，取消不留下空事件。管理关联可移除当前帖来源，最后来源移除明确预览动作删除及事件状态、时间和范围影响。普通补来源不修改事实，无来源确认补官方证据可更正同一动作；服务端复核选项给出当前无来源确认 ID，新增确认草稿按该 ID 归一为升级来源，同一动作不允许重复暂存，避免多项草稿互相覆盖。仅补来源、编辑已有动作或移除关联不改变识别进度；从当前帖子新建事件并关联有效首个动作后完成复核，不要求手填理由，由服务端记录操作说明；涉及帖子文案、识别或保留操作的旧复核仍须理由。成功刷新并保留列表条件，无关联筛选中的已关联帖自然移出；不跳转旧处理页。

- 帖子列表采用紧凑卡片，识别状态旁显示“已关联/无关联”标签，依据关联事件判断，与关联筛选口径一致；帖子编辑与顶部“创建帖子”共用帖子弹框，关联管理使用独立弹框；帖子标题直接使用 h4，第二行显示摘要，第三行账号时间及状态、计数与原帖链接两端对齐；编辑和关联按钮相对于卡片定位在右上角，始终显示；原帖在新窗口打开，事件动作编辑按钮下方不重复显示原帖链接，不从列表跳转旧处理页。创建填写配置内作者、发布时间、原帖链接、原文、中文标题摘要；不要求复核理由。人工帖子标为 processed、无付费回执，不触发采集、识别、事件、动作或通知。已有帖子的弹框只编辑标题摘要，来源身份、发布时间、原文和识别进度只读，修改保留关联动作及处理说明，服务端版本校验并审计，审计不复制原文；动作通过事件列表或帖子关联弹框管理。同一监控的同一帖子或链接重复创建须冲突，不覆盖既有记录。
- 后台列表顶部提供“创建事件”，与事件编辑共用字段和原生 dialog 弹框，复用 AdminDialog，内容滚动、底部操作固定，支持焦点约束、Escape 关闭及关闭后焦点返回触发按钮。管理员可独立创建类型、标题、摘要及范围，不自动生成动作或关联帖子；创建后进入事件列表首屏，再通过“添加动作”完善。无有效初始动作的事件仅后台展示，不进入公开列表、统计或 Webhook；后续首次有效动作及文案准备完成后发送 created，不因草稿经历基线初始化而抑制这次通知。创建、编辑与动作变更分别审计，不新增事件状态字段。
- 事件结果统一从动作推导。confirm 允许 sources=[]，公开文案只描述业务事实；到时确认说明已到预告时间，程序不解析文案区分两者，不保存 method、outcome、basisVersion 或独立 manual_verification。其余动作必须有来源。无来源确认必须填写明确生效时间；管理员通过原有添加、编辑动作流程操作，保留预览、版本校验与审计；事件动作管理无需手填理由，服务端自动记录操作说明，涉及识别或保留操作的人工复核仍要求理由，不提供“核实结果”或“人工未生效暂停推定”能力。模型只读取有来源的官方动作。
- 到时推定只由独立分钟任务保存为无来源 confirm，读取不写入。instant/deadline 取 at，range 取 through；存在待核实来源时不推定。每个当前预告只生成一次；新计划、同一预告时间覆盖、延期和取消使旧推定失效，官方和人工确认保留；人工核实已有自动确认时保留 ID，并在 monitor_state 记录内部人工身份，失效判断不得仅按 ID 前缀识别。官方确认可补充当前无来源确认的来源、文案与确认帖发布时间并保持 ID。三类事件和所有有效确认继续混合统计。
- 推定确认固定填写七语言标题与摘要，中文标题为“已到预告时间”，摘要为“预告时间已到，实际重置状态以账户显示为准”；使用固定文案，不调用模型。
- 独立每分钟确认检查共用公开结果与现有 Webhook 指纹、修订号和投递去重，首次先生成历史到期预告的确认再建立通知基线，不补历史通知；不调用模型和采集，不并入采集 tick。站点允许此检查及订阅 sweep、deliver，其余停用任务不恢复。开发测试不启用真实推送，迁移、环境变量及部署另行授权。
- 官方延期且新时间待定使用 progress 暂停预告；明确的新计划或改期统一使用 announce，包括后台对已有计划的时间更正。普通 amend 只更正业务事实，其 time 是更正的业务时间，不能替代预告计划、恢复预告或使无来源确认失效；未知计划保持未知，已知计划保持原值。业务取消为终态，不能通过新增动作恢复；错误取消只能更正或删除原取消动作后重算。模型候选的状态、时间及默认标题均基于官方事实，不将公开推定结果混入模型输入。

- 动作弹框的关联帖子以列表展示，支持多来源及逐条移除，每条来源标题直接使用 h4，移除按钮相对于顶层 li 定位在右上角，始终显示，第二行摘要，第三行账号时间与原帖链接两端对齐；“添加关联帖子”另开“选择来源帖子”弹框，不显示操作说明或 fieldset 边框及重复标题，候选列表使用随视口调整的固定高度、最大 28rem 并在内部滚动，已关联项不重复列入候选。候选按发帖时间倒序、相同时间按 ID 排序，每页 10 条；分页整行居中，上一页与下一页使用文字链接分别位于页码两侧，不可翻页时显示禁用文字；搜索后回到首页，跨页保留多选，选择确认只更新主弹框草稿，取消选择不改变草稿，最终仍由主弹框统一预览和提交；子弹框关闭及 Escape 不关闭主弹框，焦点返回添加按钮。

- 帖子保存来源、作者、发布时间、原帖链接、原文 text、随帖引用的原文 quoted_post、七语言标题摘要及必要处理记录和回执引用。不保存全文翻译、事件类型或业务状态。正式关系只有事件包含动作、动作引用帖子，不维护帖子与事件绑定表或只绑定不建动作的入口；关联事件从动作来源推导，候选不构成正式关系。正文和引用严格分开，不能把引用内容当作外层帖子动作依据。
- 帖子 processing_status 仅表达识别进度：pending（待识别）、processed（已处理）、needs_attention（待人工处理）、failed（技术失败），保留 review_reason 解释待处理和失败原因，不维护 manual 标记。是否支持动作由 sources 推导，不用状态记录有无相关事实。worker 只处理 pending，成功、需人工处理和失败写入都须核验本轮原始版本及 pending 状态；过期任务不能覆盖人工处理。动作更正、来源增删、排序不改变识别状态；从帖子新建事件并关联其有效首个动作，按人工复核完成规则设置 processed 并清空原因；帖子处理入口明确完成识别时设 processed 并清空原因，与是否生成动作无关。翻译只补文案，不改变识别状态。
- 动作独立编号且只属于一个事件，类型为 `announce`、`confirm`、`progress`、`amend`，保留七语言标题摘要、明确业务时间、事件内 sequence 和 sources 帖子引用（只存 postId）。三类事件共用 announced、in_progress、completed、cancelled 状态；confirm 均为 completed，关闭领取、到期、重开使用 progress，取消使用 amend 并设 invalidatesEvent=true，取消为业务终态，不能通过新增动作恢复，只能更正或删除错误取消动作后重算。失效事件保留历史但退出总览时间、次数和间隔统计。状态按 sequence 推导，来源发布时间仅用于公开排序和无明确业务时间时的时间依据。来源增删不改变 sequence，重排须预览后提交。不保存 result、scope、fact_key，不维护动作来源关系表。相同事实明确复用动作 ID 并补来源，不凭文案哈希判断；不同事实的同类动作分别保留，歧义转人工复核。
- 影响范围只持久化在事件。事件创建或修改、动作创建或更正、来源添加或移除、动作重排是明确分开的事务指令，不把 eventScope 藏在动作草稿中。为已有官方事实补来源不能修改事实或范围；无来源确认首次获得官方证据时明确升级同一动作的来源、标题摘要和实际时间。更正动作明确影响所有来源，删除最后来源须提示核对当前范围，不猜测历史范围。周期范围优先核验本帖已通过字面匹配的 scopeExcerpt，缺少时使用动作引文；范围引文不能替代动作证据，不把其他独立功能的限额变更借给当前事件。
- 历史导入按原帖保留摘要中的实际资格，不从旧目录推导事实或重跑识别。旧数据切换须先盘点、人工核对摘要、验证完整备份、处理旧待发回调及在途识别；离线清理旧字段和重建比较基线，保留修订号及历史记录，不补发。见 docs/deploy.md 的影响范围契约切换。
- 原文及必要随帖引用只保存在帖子，后台管理员可读取；公开响应、动作、事件和业务审计不复制原文、全文翻译、供应商原始 JSON。采集时保存原文，运行时识别、引文和时间核验只读帖子，不读采集回执正文；付费回执仍用于计费和请求续处理。历史原文仅由迁移工具从可核验的既有回执或旧帖子补回，缺失及歧义列明，不重新采集或调用模型。
- 写入及版本核验限定本次涉及的帖子、动作、事件，不锁整个监控模块或因无关事件更新而使表单失效。事件是动作管理主入口，帖子复核选择创建事件、添加动作或补充来源，不手填事件或动作 ID。
- 事件保留类型、七语言标题摘要、结构化范围和管理撤回；人工与推定均进入动作，所有出口及复核共用动作归并。通常没有有效初始预告或确认则停止公开；付费识别单独保存、等待修订的进展或修订可由该来源动作开始展示，删除该动作不产生替代初始动作。
- 普通进展、预告和修订不能覆盖有效官方确认。官方取消须有 invalidatesEvent=true 的修订动作；只有 amend 可设此标记，不从文案猜测。撤回和恢复只控制可见性，恢复前重新校验动作。关闭、到期、重开作为进展，须有针对整个活动的明确依据，不按个人到账、时间经过或模型判断改变官方事实状态；公开结果另按统一判定规则计算。
- 事件编辑不能写状态、计划时间、实际时间或确认依据。类型修改不能与已有动作冲突；动作更正、来源调整需影响预览、版本核验及单事务提交，更正后重算所有受影响事件。
- 已有动作可在后台原位修订所属事件，保留动作 ID、来源、创建时间和帖子回执；目标事件须同类型且未撤回，动作追加到目标事件顺序，预览及版本核验覆盖新旧事件。已有独立动作在人工更正类型或归属后仍可从该动作开始公开；初始动作迁出后，旧事件仍有有效来源的进展或修订也继续展示，不补造初始动作；删除动作时清理对应展示标记。
- 人工标题摘要和范围说明按编辑版本进入 worker 七语言翻译；旧翻译失效，模型不得覆盖人工原意。公开缺失文案用安全通用标题，摘要为 null；不能混用新事实和旧文案。
- 事件“编辑”表单不要求原因；标题、摘要和影响范围说明使用普通中文输入，范围只保留用户类别及说明，不要求管理员编辑 JSON。事件摘要只读保存值，空值保持为空，不维护 `summary_edited` 标记或回退动作摘要。独立翻译能力使用监控模型、仅受模型调用安全阀控制，本站三平台翻译定时已进入队列白名单，每分钟补齐展示文案；确认检查和订阅定时独立运行，不并入采集 tick。事件动作弹框（包括人工确认与来源更正）不要求手填理由，自动审计操作说明和前后差异；涉及帖子文案、识别或保留操作的旧复核仍要求理由。
- 三个监控统一支持 `direct_reset`、`reset_credit`、`bonus_credit`。奖励可领取不代表个人到账，领取截止、奖励到期与实际生效时间分别记录，奖励不计入重置次数。
- 帖子复核可对同一事件提交多个动作或给既有动作补来源；来源不明、跨作者关联不明或事实冲突时转复核，不仅按时间相近合并。未预配置产品、套餐或周期不阻止已有明确动作，不补缺失事实。

## 公开契约


- 全部监控出口使用 v2，经 publication 读取。删除监控 v1、旧站点快照与轮询接口及原文弹窗；不维护兼容分支，不影响新闻网站其他 v1 接口。
- `updates` 返回动作 `{id,action,title,summary,time,publishedAt,sources:[{postId,sourceId,url}]}`，time 必填且仅 instant/range/deadline，直接返回数据库值。来源按发布时间、帖子 ID 排序；动作按 publishedAt 倒序、ID 升序。无来源确认 sources=[]，publishedAt 取创建时间；有来源动作 publishedAt 取最早有效来源发布时间。scope.note 保留简短七语言用户说明，资格放摘要；不返回独立确认元数据。
- 预告时间取明确计划时间；官方确认取实际生效时间或日期，否则取确认动作发布时间，不沿用计划时间或后台编辑时间；自动确认取预告到期边界的单一生效时刻。其他状态取明确业务时间，否则最近有效动作发布时间。原始日期和区间保留精度。总览预告时间与最近有效确认时间独立，允许同时存在，均不取后续普通进展或修订时间。resetTime 取最新有效确认的 instant.at，最新确认只有日期、区间或截止时返回 null，不回退旧事件。历史间隔混合使用额度重置、重置卡、奖励额度三类有效事件最近 90 天的精确确认时间，官方确认、管理员核对和自动推定都参与，不按确认来源排除样本、不按事件类型拆分；每个事件只计一次，计算相邻正间隔中位数。除非使用者明确要求修改，直接沿用该口径，不再主动建议排除推定或管理员核对、拆分三类事件。预测取 resetTime 加该间隔，任一不足返回 null；过期保留原时间点，由页面标注已过预估时间，不改为今天或自动追加周期。
- 七语言为 en、zh、zh-Hant、ja、ko、ru、es。范围仅校验用户类型及文案结构，动作、来源和时间仍严格校验，翻译补全不能改变类型、动作、状态或时间。明确限制不可丢失、扩大或替换。
- 所有产品共用来源时间解析器和 Temporal，不保留作者预测或发放惯例；PST 固定 UTC−08:00，PT 按 America/Los_Angeles 夏令时规则。总览统计推算不改变动作和业务时间。
- 列表日期查询、分页、来源目录和预测规则见接口文档；站点通过 HTTP 读取 v2，日历显式使用 `Asia/Shanghai`。Agent、MCP、通知、Webhook、核验导入导出使用同一动作契约。
- 公开页面进入时一次读取当月全部事件，默认显示 3 条，“显示更多”每次追加 10 条。日期选择、再次点击取消选择、恢复整月及展开列表均在客户端使用已载入数据，不导航或重新请求；只有上月、下月切换重新加载该月。切换月份或日期筛选时重置为显示 3 条。
- 公开页概览从 `/api/v2/overview` 绑定当前平台，使用 resetTime、statistics.typicalInterval 和 sources。hasAnnouncement=true 时直接显示 announcedResetTime；无预告才使用 predictedResetTime，均无数据时显示暂无数据。时刻按北京时间显示月日时分，range 保留起止边界，deadline 显示之前；统计预测只显示月日。页面不补时间、不改变状态或重算预测。

## 运行与清理

- 经明确授权的离线历史重建使用 `scripts/offline-import.ts`：只从外部清单读取平台与来源标识，事实来自浏览器核验的 X 原文；离线识别复用正式 schema、证据与时间校验，采集与模型回执为空，不伪造供应商响应。清理默认预览、限定表白名单、核验完整备份与指纹，保留订阅、回执、预算和审计。证据与逐来源进度放 `.data/local-preview/`，缺失证据转复核；不推进采集成功截止点，不补发历史通知，不改变日常作者和回复配置。

- 模型明确无关且不需复核的帖子在 resetOnly 开启时设 filtered_out，原始记录与回执关联保留。后台默认隐藏被过滤的未关联帖子，管理员 API 可按 collectionFilter 查询正常、被过滤或全部记录；识别失败与待复核不隐藏。明确人工保留或成为有效动作来源时解除过滤，文案编辑不改变过滤。filtered_out 不属于识别进度。
- 不恢复历史初始化、每日查漏、旧处理模式或历史回复补采，不因采集配置变化重置成功截止或重筛已完成记录。账号起点在付费前保存，已有账号沿成功截止继续；未完成窗口和待识别记录按当前配置处理，全部采集和识别成功才推进截止，空结果与全过滤也可完成。补全文案校验待复核不阻断截止。
- 所有付费请求使用回执、预算、安全阀；模型共用 `monitor` 和 `MONITOR_MODEL`。TwitterAPI.io 进程内共享 5.5 秒队列，同次任务不重试。持久化失败复用 received 响应；仅搜索页网络结果未知按本文件的下一次任务恢复规则补采，模型和上下文计费未知不自动重复购买；同版本翻译待复核不反复请求。
- Webhook 变更在业务事务内登记，提交后发送；历史只建立基线，不补发。撤回已公开事件发送空事件，恢复等待有效 v2；订阅变化使旧待发任务失效。使用独立签名密钥、稳定通知 ID 及有限重试，密钥不进日志或业务审计，HTTPS 公网地址不跟重定向。
- 清除回执核对入口、字段、专属审计和其他快照内该功能内容；保留内部付费回执及无关人工审计。清除旧表及非帖子对象中的原文副本和无用字段，保留最终帖子 text 与 quoted_post；废弃代码、测试、文档、配置及状态同步清理。
- 测试只连本地假服务；实现默认不启用真实采集、模型、推送。用户明确授权开发翻译时仅在 worker 开启模型调用，保留预算和回执，其他安全阀保持关闭，不修改凭据或自动部署。

## 采集与识别

- 同作者独立帖子可按明确的事项、承诺和轮次语义关联已有事件，不要求发布时间相邻；穿插无关帖子不打断承接。回复、引用仍优先，不把语义关联伪造成帖子关系。候选提供必要来源原文并纳入版本核验；同作者或时间接近本身不足以关联，竞争解释转复核。
- 明确多轮发放按轮建立事件。同一来源可以确认前一轮并预告下一轮；模型结合已核验承诺判断总数与完成轮次，本地不按分数正则直接创建事件。全部完成不再产生下一轮。重置卡发放不等于使用重置卡。

- 第三方查询负责主帖、自回复及回复他人的筛选，本地解析、去重、保存返回结果，不重复按回复目标账号过滤；目标账号缺失不丢弃帖子。
- 引用对象保存为可复用帖子并保留自身父帖关系。上下文先从本轮响应和当前监控帖子补齐，仍缺失时按明确父帖或引用 ID 付费补采，经过预算、回执与采集安全阀；不抓整个评论区。外部作者及窗口外材料只作上下文，不自动生成官方动作。
- 按真实回复、引用关系分组，一组一次模型识别；待处理帖子与只读上下文分开，已处理帖子不自动重识别。每个动作逐帖核验证据，组内事务保存，过期结果不得覆盖人工修改。
- 付费结果先存回执，写入失败复用 received 响应；模型和上下文计费未知不自动重发，搜索页按独立任务恢复。所有采集与组处理持久完成才推进成功截止，明确歧义转人工，不将网络失败当作父帖不存在。
