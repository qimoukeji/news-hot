# 共享重置监控引擎

此目录是 Codex、Claude 及后续 AI 重置监控共用的实现，不在站点清单中单独安装。

- 三个监控统一启用 `direct_reset`、`reset_credit`、`bonus_credit`，使用共享常量、提示词模板与通用校验。语义见根目录 `CONTEXT.md`。
- 账号、显示名、默认产品、作者时间策略、套餐集中在 `site/reset-monitors.ts`；不包含凭据。产品专属语义留在对应模块，共享引擎不得写死账号或产品。
- 时间策略按实际作者和时间证据选择，默认只解析明确时间。作者预测仅适用于显式绑定的账号，奖励不预测。新事件保存时间策略，公开投影按事件读取，历史记录不回填。
- 奖励额度保留金额或用量原话、资格条件、领取方式、领取截止与到期；时间只按独立来源中的明确时间和时区转换，未知保留原话。领取截止不能写成生效时间，官方可领取不能写成个人已到账；不生成模型预计时间或重置次数，统计、日历和通知按类型区分。
- 新建活动必须有非回复主帖动作证据；同一活动的补充可通过已核验的主帖引用关系关联，但不能把父帖引文冒充主帖证据。明确动作与规则冲突须留复核原因，不得静默丢弃。
- 卡和奖励活动的后续提醒不能沿用直接重置的短候选窗口；回顾性确认缺少唯一目标时转复核，不以提醒日新增发放。明确额度周期从已核验的动作引文保留，不能借用同帖其他限额调整。
- 仅有 X Article 链接且正文未保存时标记资料不完整，不得标成已确定无关或创建事件；公开健康与后台复核须反映这一限制。

- `definition.ts`、`contracts.ts`：无后端依赖的配置和共享类型；`backend/` 与运行配置不得进入浏览器。
- `backend/`、`api/`、`web/`：共享采集、事件处理、人工复核、公开投影与页面。供应商格式仅在 `backend/providers/` 处理。
- `migrations/`：共享监控表的新迁移，一文件一语句；Codex 历史迁移留在原目录不改。
- `tests/`：通用行为、监控隔离、迁移与扩展测试，数据库必须以 `_test` 或 `_ci` 结尾；外部请求仅连接本地假服务。
- AI 专属提示词补充及作者时间策略放在各自模块，套餐来自站点配置，共享引擎不得写死作者、产品或发放惯例。
- 模块可提供默认产品、范围冲突及跨作者关联策略；要求明确跨作者依据的模块不能只靠时间相近关联不同作者的事件。产品默认值仅补缺失值，不覆盖已有事件或人工字段。原始模型结果必须保留。
- 专属非重置规则通过可选 `excludeProposition` 返回排除原因。引擎保留命题编号、原始模型结果及排除原因，排除命题不能参与事件、复核或关联；全部排除且无故障线索时归为无关，人工复核仍由管理员决定。
- 所有重置监控共用 `monitor` 模型能力及 `MONITOR_MODEL`，未指定时使用 `LLM_*` 默认模型；模块不提供独立模型选择配置。
- 供应商请求通过共享预算控制。TwitterAPI.io 免费套餐真实返回 HTTP 429，要求至少 5 秒间隔；适配器固定间隔 5.5 秒，进程内所有监控共用等待队列，不提供环境变量配置。失败释放队列但不重试请求。
- 所有数据库读写绑定服务端监控定义；主键与外键包含 `monitor_id`。调用者不能通过 HTTP 输入改变监控范围。
- 保留 Codex 的入口、运行名称、历史标识和行为。其他监控名称由监控 ID 生成。
- 离线数据与临时工具放 `.data/local-preview/`，不提交凭据或生产快照。架构与新增监控步骤写在 README。
- 公共 v2 接口使用严格契约，经 publication 模块入口读取。type 只区分 direct_reset、reset_credit、bonus_credit；预告使用 status=announced，不返回或保存 announcement。事件的 time 直接保存 ISO 8601 字符串（带时区时间戳、纯日期或起止时间戳区间），不使用对象、null 或 unknown。announced 优先明确计划时间，确认后使用实际时间／日期，否则取同一事件最后已接受业务更新（announce、progress、confirm、amend、withdraw）的原帖发布时间。不使用数据库编辑时间、无关帖或当前时间；首次发布时间固定，时间经过不改业务状态。内部 timeBasis 区分明确来源时间 source 与默认 latest_update，不进入公开响应；奖励领取截止、到期及内部解析仍保留结构化精度。
- v2 用户范围没有明确说明时默认 all_users；已有 paid_users、selected_users 及产品、套餐、额度窗口保留。scope.note 公开时必须是七语言非空文本：all_users 固定“所有用户”，paid_users 固定“付费用户”，selected_users 必须提供具体用户条件，缺失时不得发布。默认值在统一公开投影和后续补全中应用，不重写历史原文或识别结果。本站 Codex、Claude 的额度窗口目录包含 five-hour、weekly、monthly；Grok 保留原目录，不为事件自动添加未声明的月额度范围。
- 自动补全必须以已接受的事件范围为约束，代码核对明确用户类型、产品、套餐和额度窗口；模型丢失、扩大或替换这些限制时转待复核，不能只靠提示词维护人工结论。无法映射到公开目录的明确限制也转待复核，不当作未说明。
- v2 事件文案只保留 title 与 summary，不返回或保存 details；核验包、模型补全及消费端使用同一规则，旧字段必须清理，原始帖子与审计保留。
- v2 列表事件不返回 bonusCredit 字段（包括 null）；奖励事件仍使用 type=bonus_credit，并保留标题、摘要、范围和更新。内部事件投影、核验、奖励处理及已存 bonusCredit 保留，列表契约与内部事件契约分别校验。
- v2 的列表与内部事件投影按 time 倒序、ID 升序排列，区间取起点。公开 time 的精确时间和区间两端统一输出 UTC（Z），纯日期保留原样；纯日期排序仅按 UTC 零点比较，不代表实际发生时刻，查询时区不改变排序。列表根只有 list/pagination；from/to 只接受日期，timeZone 接受 IANA 命名时区、空值默认 UTC，日期全空查所选时区本月，单边补所在月边界，最多六个自然月。精确时间按当地 from 零点至 to 次日零点的左闭右开范围筛选，区间取起点，纯日期直接比较。limit 空值返回范围内全部数据，有值为 1–100 并使用绑定平台、有效日期、规范化时区和 limit 的游标；非法参数返回 400。
- v2 总览独立由站点注册一次，聚合各平台 sources/catalog/statistics 与三个标量时间：predictedResetTime 按历史已完成直接重置间隔推算，过期返回北京时间明天日期；announcedResetTime/resetTime 只检查全部类型按 time 排序的最近一条，按是否 announced 互斥返回。派生时间不落库，不改变识别事实。公开不再返回旧 overview/history/calendar 或旧三个字段。
- v2 总览各平台的 sources 只列账号或发布主体及主页，按账号去重，保留配置账号及公开事件关联的历史账号。事件返回非空 updates，逐条包含原帖 id、action、publishedAt、七语言 summary 或 null、source:{sourceId,url}。只包含已接受的 announce、confirm、progress、amend、withdraw 关联，按发布时间倒序、ID 升序；同一事件内更新 ID 唯一。sourceId 引用总览对应平台的 sources，url 使用各自已存原帖地址，引用缺失或 URL 不合法时失败。不返回 primarySource/sourceIds，不拼接地址，不因更新条数增加事件统计。更新摘要与原帖证据绑定，内容失效时不公开旧摘要。
- 核验后的七语言文本、范围、时间与证据保存在现有 `presentation.publicV2`。自动生成与人工核验导入的 time 在写入前共用 UTC 归一化，精确时间和区间两端使用 Z，纯日期保留原样。预览展示归一化后的待写入值，审计记录实际保存值；不批量重写历史数据或改动来源时间依据。内容依据变化后旧补充信息不再公开；数据整理命令默认只导出或预览，正式库应用需另行确认，不修改表结构、不请求外部服务。详细规则见 `docs/reset-monitor-v2.md`。
- v2 的明确月日、时分可按使用者口径自动补全年份与时区：明示值优先，缺年份按同一活动首次公告的时间确定并处理跨年，缺时区先用同帖、再用同一活动的明示时区，均无时区时使用数据库原帖时间戳的统一归档时区 UTC。记录原话、来源与补全依据；仅日期保留 date，不补成午夜，不使用当前年份或滚动延长已确定的日期。此规则不改变 v1、自动识别安全阀或采集模式。

- 增量 v2 与识别共用 monitor 模型能力及回执预算；模型只提供业务文案和有引文支持的结构化事实，状态、首次发布时间、时间补全与统计由代码约束。内部证据、模型版本和回执不进入七语言文案。人工修改使旧内容失效后，worker 可重新生成；版本冲突不得覆盖新的人工结论。实现和测试不启用真实采集、模型或推送，不自动部署。
- v2 无效响应的拒绝回执与 needs_review 状态在同一事务提交；提交前保留 received 响应，进程退出或持久化故障后复用原响应重新校验，不购买第二份答复。普通模型调用保持既有无效响应处理方式。

- v2 活动关闭只接受关联原帖中明确针对整个活动的陈述；条件句、个人账户描述、否定、提问和未来安排不能改变活动状态。简写提醒不得抹掉同一截止日期已有的时分，明确修改才替换；显式时区必须完整解析，不支持或冲突时保留未知。next/last 星期保留相对周语义，明确时间区间保留 range，不进入精确时刻间隔样本。

- 采集只有一条流程：增量非回复主帖 → 模型识别 → 关联事件 → v2 补全。所有监控统一排除回复（含自回复）与纯转推，保留外层非回复的引用帖；供应商查询和入库前都校验，不按正文关键词筛主帖。
- 不保留旧处理模式、关键词回复筛选、历史初始化、每日查漏或回复父帖补采入口。引用正文只使用采集响应附带的内容，不发额外上下文请求。历史事件及其原帖、证据、回执、人工审计保留。
- 账号首次观察时间在付费前保存；新账号从观察时间向前采集。已有账号沿现有成功截止继续，收紧范围不改变原截止、不跳过停机期间主帖。全部分页与识别成功才推进截止，v2 业务校验待复核不阻断截止；付费调用经过回执、预算和停止检查。
- 历史清理先预览并备份；保留全部事件及直接、间接引用的证据帖，删除无关联采集帖和已移除流程状态。不得改写事件事实、撤回事件、付费回执或人工审计。
