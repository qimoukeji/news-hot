# 共享重置监控引擎

后台列表顶部可人工创建事件，与事件编辑共用类型、标题、摘要和影响范围表单。创建只保存事件信息，不带动作或来源；创建后回到事件列表，通过卡片的“添加动作”完善。没有有效初始动作时仅后台可见，不进入公开接口、统计或 Webhook；添加有效动作且文案准备完成后才首次推送。

帖子列表使用紧凑卡片，提供“编辑”“创建帖子”和“关联事件/管理关联”弹框。人工创建填写来源作者、发布时间、链接、原文及中文标题摘要，保存为已处理来源，不自动识别或生成事件动作；已有帖子只编辑标题摘要，保留来源与识别状态。关联主弹框不显示顶部帖子信息，按事件分组展示当前关联。关联已有事件和新建事件按钮位于当前关联标题右侧，独立子弹框只暂存来源、新动作或新事件及首个动作，可组合多项变更并逐项撤销；主弹框底部先预览影响，再统一保存，不要求手填理由；从帖子新建事件并将当前帖子关联到有效首个动作，视为完成该帖人工复核，预览展示状态与原因变化，保存时同一事务设为 processed 并清空 review_reason，原状态与原因保留审计；仅补已有动作来源、编辑动作或移除关联仍不改变识别状态。取消不留下空事件。管理关联可移除来源，最后来源移除须预览动作删除及事件影响。创建后按帖子发布时间定位日期列表，编辑后保留原筛选和页码；原文仅后台可见，不复制到审计。

Codex、Claude、Grok 共用一条流程：**按平台配置增量采集 → 可选关键词初筛 → 模型提出动作与相关性 → 校验来源及事实 → 聚合事件 → 补齐七语言文案**。所有公开出口通过 publication 的 v2 投影读取，读请求不触发模型。

## 数据与事件

事件识别已确认有额度动作、但原文未明确细分类型时，默认按“额度重置”（direct_reset）处理；明确可兑换的重置次数或重置卡才归为 reset_credit，明确独立消费池的一次性奖励额度才归为 bonus_credit。唯一可核验的后续帖沿用已有事件类型。默认或继承类型时 kindExplicit=false，不单因类型未细分而转复核；动作依据、关联和上下文仍须核验。

自动识别逐项核验动作：一帖中明确事实先保存，未解决的关联或其他事实保留待处理原因，因此帖子可以同时“已关联”和“待处理”。worker 不自动重跑这类帖子，也不重复生成已接受动作。确认按具体事实分句核验，相邻问句、your 等代词不否定独立完成句；未来、条件、否定、个人感受不能作为官方确认。

关联沿可核验的父帖、引用链及明确原帖链接查找唯一事件，校验作者、时间、循环与事件类型；先补齐必要上下文，没有唯一依据继续复核，不按作者或时间接近合并。简短完成句可以继承该事件的对象和未变范围，引用不能替代当前帖子自己的动作依据。“下一小时内”等从发帖时刻解析为区间；EOD 使用明确来源时区的当日结束边界；几分钟、soon 等不猜数字，明确动作可保存但不形成到时推定计划。

| 对象 | 内容 | 关系 |
| --- | --- | --- |
| 帖子 | 来源、作者、发布时间、原帖链接、原文与随帖引用、七语言标题摘要、必要处理记录 | 通过支持的动作关联事件 |
| 动作 | 独立 ID、类型、七语言标题摘要、明确业务时间与事实变化 | 只属于一个事件，可有多个帖子来源；确认可无来源 |
| 事件 | 类型、七语言标题摘要、结构化范围、管理可见性 | 聚合动作得到当前状态和时间 |

动作分为 `announce`、`confirm`、`progress`、`amend`。新事件必须由预告或确认建立。三类事件有效确认均为 completed；关闭领取、到期、重开使用 progress，取消使用带 invalidatesEvent=true 的 amend，取消为业务终态，只能更正或删除错误取消动作后重算。普通修订不覆盖有效官方确认；旧无来源确认按预告和计划变化重算，失效事件保留历史但退出总览时间和统计。同一事实明确复用已有动作 ID 并补来源，不按标题摘要哈希去重；不同事实分别保留，歧义转人工复核。

动作的 sources 数组只存 `{postId}`，动作以事件内 `sequence` 维护事实顺序；增删来源不改变顺序。正式关系只有事件包含动作、动作引用帖子，不维护独立帖子事件绑定。影响范围只存事件，事件修改、动作更正、来源调整和顺序调整分开表达、一次事务提交。

识别的范围说明 `scope.note` 使用简洁的七语言标签，中文写“所有用户”或“付费用户”，不重复产品名、“所有账号”等措辞。多个付费套餐并列（如 Plus、Pro、Business）统一概括为“付费用户”，单一套餐仍写“Max 用户”等具体名称；包含免费套餐的组合不能概括为“付费用户”。付费用户标签不追加注册、升级截止时间、领取条件、周期或受影响人数等细节，这些事实完整保留在七语言摘要、原始证据和结构化范围中。特定用户的条件可在动作摘要中核验，不能因标签变短而扩大实际范围。历史记录精简标签前须确认摘要已保留条件，缺失时同步补充；领取步骤、使用方式和“未说明周期”等缺失信息不写进范围标签。

事件状态和时间统一由动作推导。只有 confirm 允许 sources=[]，标题或摘要说明“人工核实已生效”或“已到预告时间”；程序不解析文案来区分两者，也不保存 method、outcome、basisVersion 或独立人工结论字段。官方取消、官方确认优先于无来源确认；预告、进展和普通修订不覆盖有效官方确认。管理员撤回控制可见性，失去有效初始动作停止公开。奖励开放领取不代表个人到账。

有明确计划时间的预告由独立分钟任务保存一条无来源确认：精确时间到点、日期按北京时间次日零点、区间按末端触发；缺少计划时间、仍在进行或来源存在事实冲突时不推定。管理员通过原有添加、编辑动作流程核实已生效，填写实际时间与文案，保留理由、预览、版本校验和审计；不提供“核实结果”或人工未生效暂停流程。后续官方确认补充同一动作的 sources、标题、摘要与实际时间，保持动作 ID。新预告、明确计划时间修订、延期、取消使旧无来源确认不再决定当前结果，动作及审计历史保留。所有有效确认都计入统计，每个事件只计一次，日期与区间不进入精确间隔样本。API 不返回 confirmation 或 resetConfirmation，模型只读取有来源的官方事实。

独立每分钟确认检查与订阅 sweep、deliver 通过站点白名单运行，不调用模型或采集。首次启用先生成历史到期预告的确认，再建立当前通知基线，保留修订号，不补发历史内容；后续推定、人工确认、官方补证与修正沿现有 Webhook 发送，使用事件指纹和修订号去重。读页面和接口不写库、不临时生成确认，最多下一分钟检查后出现结果，并受最长 60 秒缓存影响。推送安全阀不自动开启。

预告使用明确计划时间；有来源确认使用实际生效时间或日期，缺失时使用确认来源发布时间，不沿用预告或后台编辑时间。无来源确认必须填写明确时间，人工使用核实的实际时间，推定使用明确计划时间。其他状态使用明确业务时间，否则使用最近有效动作发布时间。有来源动作的发布时间取最早有效来源帖时间，无来源确认取动作创建时间，该发布时间不充当生效时间。日期和区间保留精度，精确时间统一 UTC。

所有产品共用基于 Temporal 的来源时间解析，不按作者预测发放时间。PST 固定 UTC−08:00，PT 按 America/Los_Angeles 夏令时规则；缺年份、时区及相对时间使用统一 v2 规则，显式冲突转复核。总览的历史间隔预测只作派生信息，不影响动作时间或状态。

帖子保存原文 text 和必要的随帖引用 quoted_post，不保存全文翻译。采集直接写帖子，后续识别、引文与时间校验只读帖子，不从采集回执恢复正文。管理员后台可查看原文；公开接口、动作、事件和业务审计不复制原文。供应商原始 JSON 仅保留内部付费回执，用于计费与付费请求续处理。

帖子识别进度仅有 pending、processed、needs_attention、failed，保留 review_reason，不维护 manual。是否支持动作从 sources 推导；成功识别无论有没有动作均为 processed。worker 只处理 pending，结果写入核验原始版本与 pending 状态，不能覆盖后续人工处理；动作更正、来源增删、重排及翻译不改变识别状态。帖子处理入口明确完成识别后设 processed 并清空原因。从帖子新建事件并关联该帖有效首个动作，同样在预览后完成人工复核；普通来源增删与已有动作编辑保持识别状态。

## 后台与公开入口

“所有用户”“付费用户”和 unknown 用户、产品及其组合等固定范围标签，缺少语言时可由共享标准译文在公开投影中补齐，已有非空语言必须全部对应同一个标准标签。仅补显示文案，不推断或修改 scope.type、目录代码，不调用模型或写数据库；自定义资格条件、冲突的部分译文及 selected_users 仍须完整翻译。这样中文固定标签不会因翻译任务停用而隐藏已有有效动作的事件，其他标题摘要仍使用原有安全展示规则。

明确动作可在影响范围目录映射不全时入库并关联事件。用户范围未知使用现有 `scope.type=unknown` 与“unknown 所有用户”标签；产品无法完整映射使用空 `productCodes` 与“unknown 所有产品”，两者可组合。unknown 表示该维度未限定查询范围，不表示已证实覆盖全部。保留已核实代码和摘要中的实际限制，不把未知产品换成默认产品、未知周期换成相近周期；普通补来源不能覆盖既有已知范围。前后台、API、Agent、MCP、Webhook 使用同一结果，不新增范围字段或目录代码。

三个产品的后台基础路径分别是 `/admin/codex-reset`、`/admin/claude-reset`、`/admin/grok-reset`；Codex 后台 API 使用 `/api/admin/codex-reset`，不保留旧路径兼容。基础页分为“事件列表”和“帖子列表”两个 tab，默认事件列表，以 kind=events/posts 切换。筛选区只保留北京时间开始日期 from、结束日期 to（包含当天）。事件按最新来源时间筛选和排序，卡片与动作行复用公开页布局，首行显示类型、范围、状态和事件时间，下方显示标题、摘要及默认展开的动作和全部来源；管理按钮、数量与最新来源时间放在卡片底部，时间线可收起。帖子列表包含已关联与未关联帖子，默认隐藏被过滤记录，按发布时间筛选和排序，显示关联事件及弹框入口。两个列表各自分页；切换时保留时间范围并清除页码，重置仅清除当前列表时间范围。`/events/:id` 复用列表时间线管理动作和来源，动作顺序单独弹框预览提交；帖子在列表管理关联弹框中完成保留与人工复核，旧 `/posts/:id/review` 和独立 `/posts` 页面均返回 404。

事件列表通过“添加动作”和每条动作唯一的“编辑”按钮打开弹框；事件标题保留详情入口，详情页管理全部动作与顺序。来源帖的原文和链接在帖子编辑弹框核对，识别状态用中性、绿色、黄色、红色标签表示待识别、已处理、待处理、处理失败，不再显示“处理帖子”链接；帖子列表提供编辑和管理关联弹框。

动作弹框每次打开读取最新事件复核数据，固定目标事件，复用动作字段、来源选择器与影响预览。标题、摘要使用整行输入；来源支持多条，已关联帖子以列表显示标题、作者、发布时间、摘要和原帖链接，可逐条移除。“添加关联帖子”另开选择弹框，支持搜索、多选，已关联项不重复显示；确认只更新主弹框草稿，取消或 Escape 只关闭选择框，保留主弹框输入。新增默认预告且不预选来源；确认允许无来源，但必须填写明确生效时间并以标题摘要说明人工核实，其他动作至少选择一条。没有有效初始动作时仅允许预告或确认。编辑预填动作与全部来源，增删只提交差异，更正共享事实提示影响全部来源。动作操作由服务端记录审计说明，不要求手填理由；保留帖子和完成处理必须填写复核理由。先预览再确认，修改后预览失效；已有来源的动作删除最后来源仍提示删除动作及事件影响，不自动改成无来源确认或恢复历史范围。成功后关闭并刷新原列表，保留 tab、日期和页码；取消不写入，加载失败可重试，提交失败保留输入，版本冲突须重新读取后预览。已撤回事件禁止新增动作和来源，不修改事件范围、动作顺序或帖子识别进度。

事件“编辑”不要求原因，影响范围说明与标题一样使用普通中文输入，结构化代码原样保留。摘要直接使用事件保存值，清空后不从动作补回。事件、动作及帖子创建或编辑后，由各平台独立的 worker 分钟任务使用配置的监控模型补齐七语言；帖子处于 pending、processed、needs_attention 或 failed 均可翻译，是否关联动作不影响补齐文案。翻译只提交保存的标题、摘要与范围说明，不提交原帖全文；保留已有语言并核验记录版本，不修改识别状态、处理原因、关联、动作顺序、业务时间或状态。相同完整文案不重复请求，失败版本不反复购买，新编辑生成的新版本会重新判断。开发环境经用户开启翻译后，仅 worker 的模型安全阀打开，采集、识别和真实推送仍关闭；不依赖采集开关，模型调用安全阀关闭时保持待处理。

公开接口为 `/api/v2/overview` 及三个 `/api/v2/<平台>-resets` 列表，详见[严格契约](../../docs/reset-monitor-v2.md)和静态生成的 `/openapi-v2.json`。`updates` 是动作数组，含动作 ID、类型、七语言标题摘要、业务时间 `time`、发布时间与全部 `{postId,sourceId,url}` 来源。业务时间未明确时为 null，前后台时间线左侧显示“—”，不以发布时间代替。统计按事件计算，不因帖子或动作数量增加；内部与外部使用相同 v2 形状，不含 `bonusCredit`（包括 null）。监控 v1、旧站点数据及版本轮询接口均删除，无兼容模式；`/openapi-v1.json` 只移除监控路径及孤立 schema，其他新闻 v1 保留。

站点只通过 HTTP 获取 v2 总览和当月全部事件，日历显式使用 `Asia/Shanghai`，时间线展示动作和全部来源链接。列表初始显示 3 条，“显示更多”每次追加 10 条；选日期、再次点击取消日期、恢复整月和展开列表均使用本地已载入数据，不重新请求。切换上月、下月才加载对应月份，月份或日期筛选变化后从 3 条重新展示；历史日期直达链接仍加载对应整月后按日期筛选。日历日期悬停显示当天事件数，包含 0 个事件，计数来自当月已载入数据。Agent、MCP、飞书和 Webhook 使用相同投影。Webhook 在 `/admin/reset-subscriptions` 管理，历史只建立当前基线、不补发；撤回发空事件，恢复等待有效内容，详见[订阅协议](../../docs/reset-monitor-webhooks.md)。`WEBHOOK_PUSH_ENABLED` 默认关闭。

## 采集与运行

完整流程见[采集、上下文补齐与按串识别](../../docs/reset-monitor-collection.md)。先完整分页、展开引用、补齐父帖，再按明确回复与引用关系分组，每组调用一次模型；待处理业务帖子与只读上下文分开，已有处理结果不自动重跑。辅助材料使用 context_only 标记，不独立进入识别、默认业务帖子统计或官方动作来源。组内每项事实绑定具体原帖并一次事务保存，失败复用已收到的回执；计费未知不自动重发。


公开页标题为“产品 今天会重置吗？”，副标题使用配置的监控账号。标题下先展示日期卡：`announcedResetTime` 非空时显示“公开预告”和该日期，否则显示“预估时间”和 `predictedResetTime`。其下概览使用 `/api/v2/overview` 中当前平台的 `resetTime`、`statistics.typicalInterval` 和 `sources`，依次展示最近重置、重置间隔和来源账号。所有日期按北京时间显示，日期精度不补造钟点；最近重置始终独立读取 `resetTime`，缺失值显示“暂无记录／数据／预估”，不在浏览器重新计算预测。

账号、显示名、默认产品、套餐、公开目录及采集选项在 `site/reset-monitors.ts`，产品专属规则留各产品模块。统一启用 `direct_reset`、`reset_credit`、`bonus_credit`。主帖始终开启；各平台分别配置 `collection.includeReplies`（回复他人）、`collection.includeSelfReplies`（自回复）和 `collection.resetOnly`（关键词加模型过滤）；本站三个平台设为 includeReplies=false、includeSelfReplies=true、resetOnly=false，采集主帖及自回复。只采配置账号自己发布的内容，不采其他人的回复；纯转推始终排除，引用帖保留。

```ts
collection: {
  includeReplies: false,
  includeSelfReplies: true,
  resetOnly: false,
  keywords: ["reset", "resets", "resetting", "banked", "credit", "credits", "重置", "额度", "額度"],
}
```

| --- | --- | --- |
| false | false | 主帖 |
| true | false | 主帖及回复他人 |
| false | true | 主帖及自回复 |
| true | true | 主帖及全部回复 |

第三方查询负责主帖和回复类型筛选，本地接收、解析、去重并保存返回结果，不再按回复目标账号重复分类，也不因字段缺失丢弃帖子。关键词只用于构造查询，明确无关内容仍由现有识别模型判断。

开启 resetOnly 时词表不得为空，按字面关键词 OR 查询，再复用现有模型确认三类额度事件及后续消息，不增加独立过滤模型。英文忽略大小写，不自动扩展词形；中文按包含匹配，词表不能注入搜索操作符。关键词初筛可能漏掉“All done”“OK fine”等未命中词表的相关短回复，模型无法补回。

回复保存供应商提供的 `reply_to` 父帖 ID、目标账号，缺失值保持为空，不影响收录。上下文依次从本轮响应、当前监控已保存帖子及供应商按 ID 查询补齐，引用帖保留自身父帖关系；父帖和引用只帮助确定对象，不能代替回复自身的动作依据。关联不明或只有 X Article 链接而缺内容时转人工复核。

模型明确无关且无需复核时保留帖子及回执关联，设置 `filtered_out`；后台默认隐藏被过滤的未关联帖子，可按“采集记录”切换正常记录、被过滤、全部。识别失败和待复核不作为无关隐藏。人工“保留帖子”或给有效动作补来源会解除过滤，普通文案编辑不改变过滤标记；过滤不增加识别进度状态，公开接口保持不变。

默认 SocialData、15 分钟，也支持 TwitterAPI.io。供应商共用凭据、付费回执、预算和安全阀，TwitterAPI.io 在进程内共用 5.5 秒请求队列。原始响应先存回执，再校验处理；失败中止本轮，本轮不自动重试付费请求。下一次独立定时任务沿固定窗口和同一回执 key 续处理，已收到的页直接复用；仅明确未受理的 HTTP 拒绝可在下一轮重试，计费未知或收费响应 schema 无效均不自动重发。

新安装或新增提供商首先保存当前起点，不采历史；已有账号沿成功截止继续完整窗口，不跳过停机期间内容。配置变化不重置成功截止、不回补已完成窗口的历史回复、不重筛已完成记录；未完成窗口和待识别记录按当前配置处理。首次起点在付费前保存，失败不漂移。全部采集和识别成功才推进截止，空结果和全部被过滤也可完成；已接受事实后的文案补全校验失败使翻译任务待复核，不改帖子识别进度、不阻断截止。持久化中断复用 received 响应，同版本翻译任务待复核不反复购买，计费未知不能自动重发。没有历史初始化、每日查漏、旧处理模式或历史回复补采入口。

## 定点上下文修复

`node --env-file-if-exists=.env modules/reset-monitor/scripts/thread-repair.ts --platform <codex|claude|grok> --receipts <回执ID列表> --targets <目标帖子ID列表>` 默认只读预览，仅恢复选择的回执及明确祖先中可核验的材料。正式应用需停止 worker、关闭采集与模型和通知，提供完整备份与预览指纹，再增加 `--apply --worker-stopped --fingerprint <指纹> --backup <备份.dump>`。已处理帖子不重跑；只有明确指定的 needs_attention 帖子重新进入 pending。工具不购买内容或识别、不改事件动作、不回退检查点，历史目标的后续处理抑制真实通知。

## 数据库与维护

当前实现只读取动作三表，旧格式转换器、阶段迁移 CLI 和旧表探测已退出；历史 SQL 保留，新安装仍执行完整迁移。旧结构部署按[重新部署与数据导入](../../docs/deploy.md#重新部署与数据导入)从当前结构的完整备份恢复到空库，不依赖未提供的中间转换版本。删表迁移拒绝非空旧表。

当前格式的离线重建、v2 导入导出和上下文修复继续保留，使用独立 backend/backup.ts 验证完整备份，并执行各自的版本、指纹及审计校验。备份须包含全部业务表的结构和数据，并在独立空库实际恢复成功；维护连接需要建库权限，失败则拒绝清理和修复，临时库在成功或失败后删除。旧帖子处理页面不再注册，所有帖子操作使用列表弹框；事件详情复用列表时间线，动作顺序独立预览提交。

## 离线历史重建

经明确授权后，可使用 `scripts/offline-import.ts` 的 `--phase clear|import|finish` 重建历史数据。默认只读预览；应用必须提供 `--apply --worker-stopped --target <预览目标> --fingerprint <预览指纹>`。清理另需 `--backup <已验证可恢复的完整备份>`，只清除监控内容、运行状态与历史通知，保留订阅、付费回执、预算和审计；具体清理表见[部署说明](../../docs/deploy.md#离线重建重置监控)。

导入阶段使用 `--bundle <JSON文件>`。文件包含 `version: 1`、`capturedAt`、`sources`；每条来源包含平台 `monitorId`、帖子 `id`、`url`、`evidencePath` 和 `status`。`observed` 还需原文 `text`、`author`、精确 `publishedAt`，可附 `quotedPost`、`replyTo`、正式识别结构 `recognition`；`unavailable` 只记录 `reason`，不伪造原文或时间。证据文件必须存在，逐来源结果返回证据 SHA。来源与模型回执均为空。

该入口只在本次作用域接纳清单中已核验的作者，不修改站点常态采集配置，不从引用账号扩大信任。先保存全部原帖，再按发布时间执行与正式模型相同的校验；缺少识别结果时保持 pending，可补材料续处理。已处理和待复核记录不会自动重筛。`source:<postId>` 只能解析唯一事件或匹配动作；同一来源涉及多个事件时，先导入初始事实，再使用当前数据库中核实的事件 ID 处理后续来源。范围周期由本帖范围引文核定，动作和时间仍由动作自身引文核验。

`finish` 拒绝仍有 pending/failed 的导入，重建通知基线、不补发历史通知，也不写采集成功截止点。整个流程保持采集、模型和推送安全阀关闭；原文与浏览器证据仅保存在后台帖子和忽略提交的本地资料目录。
