# Claude 额度动态

后台基础路径 `/admin/claude-reset` 分为“事件列表”和“帖子列表”两个 tab，默认事件列表，以 kind=events/posts 切换。只提供北京时间开始日期 from、结束日期 to 筛选（包含当天），各自分页，切换保留时间范围并清除页码。事件按最新来源时间筛选和排序，下方默认展开动作及来源；帖子列表包含已关联与未关联帖子，按发布时间筛选和排序。`/events/:id` 管理事件并复用列表时间线和弹框；帖子在列表弹框内管理，旧 `/posts/:id/review` 和独立 `/posts` 页面均不提供。

本目录仅保留 Claude 配置、产品策略、提示词及共享引擎薄入口。通用代码和新增迁移放 `../reset-monitor/`，执行该目录 `AGENTS.md` 及根目录规则，不复制实现或另建产品表。

- 主信源是 `site/reset-monitors.ts` 的非空账号名单，初始为 `@ClaudeDevs`；未配置作者仅作上下文，不能提供官方承诺。页面名称使用“Claude 额度动态”，现有模块、页面和任务标识保留。
- 共用 `monitor` 模型能力和 `MONITOR_MODEL`，未指定时沿用 `LLM_*` 默认模型，不提供产品独立选择。
- 启用 `direct_reset`、`reset_credit`、`bonus_credit`。官方一次性云会话赠额属于奖励；API 赠金、每月 API credits、额度提升、普通限额调整及日常自动重置不生成事件。消费池不等于重置次数，不能仅凭 claim/credit 或截止时间判为重置卡。
- 产品专属排除通过 `excludeProposition` 接入，保留结构化命题编号和排除原因；原始响应仅留付费回执。混合帖子逐项处理，不因赠额排除真实重置，人工可更正自动判断。
- 原文和随帖引用仅保存在帖子，运行识别直接读帖子；不存全文翻译，原文不进事件、动作、公开响应或审计。供应商原始响应仅留付费回执供计费及请求续处理。
- 帖子 processing_status 只表达识别进度：pending、processed、needs_attention、failed，保留 review_reason，不维护 manual。是否支持动作从 sources 判断；worker 只处理 pending，写入核验原始版本和 pending 状态。动作、来源和重排不改识别进度，明确完成帖子处理才设 processed 并清空原因，翻译只补文案。
- 动作使用预告、确认、进展、修订，一个动作可有多个来源，同帖可支持多个动作。只有 confirm 可无来源且须明确生效时间，标题摘要说明人工核实或推定；事件状态时间统一由动作推导，不保存独立人工字段或判定元数据。人工确认复用原有动作流程，不提供核实结果或人工未生效暂停。模型只读有来源官方动作。同一事实补来源，不重复建动作；新事件从预告或确认建立。
- 三类事件共用状态与动作规则；有效 confirm 均为 completed，官方确认优先于无来源确认；新预告、计划修订、延期、取消可使旧无来源确认不再决定结果。领取关闭、到期、重开使用 progress，取消使用 amend 并设 invalidatesEvent=true，取消为业务终态，只能更正或删除错误取消动作后重算。正式关系只有事件包含动作、动作引用帖子，不维护独立绑定；sources只postId，sequence属于动作。范围只在事件保存，事件、动作、来源、顺序变更分开表达。为已有官方事实补来源不能更正共享事实；无来源确认获得官方证据时更新同一动作来源、标题摘要及实际时间并保持 ID，关联不明转复核。
- 事件编辑仅类型、标题、摘要和范围，撤回与恢复独立控制可见性；无账户回执核对。动作及来源更正需理由、影响预览、版本核验和单事务提交，然后重算事件；翻译与事实编辑版本绑定。
- 事件页管理动作，帖子复核通过选择器创建事件、添加动作或补来源，不手写 ID；事件创建或范围更新、动作创建或更正、来源增删、顺序重排分组提交，动作草稿不含事件类型或范围。只核验并锁定相关记录，补来源不改 sequence。
- 明确套餐、产品及额度周期忠实保留，进展不能扩大范围。一次性奖励后续细则可由已核验的官方线程指向同一活动，但不能当作新发放。订阅资格、领取方式及使用前提分别表达。
- 奖励可领取仅表示活动开放，不表示个人到账；领取截止与到期分别保存明确事实，不充当生效时间。关闭、到期和重开须有针对活动的动作依据。
- 时间只按明确来源解析，不使用作者惯例或模型预测；缺年份、时区按共享 v2 规则补全，显式冲突转复核。有来源确认无实际时间取确认来源发布时间；无来源确认必须填写明确时间，不能用创建时间补缺。明确计划到期由独立分钟任务保存推定确认，不能当成官方完成事实。
- 所有监控出口使用 v2，站点仅经 HTTP 读取，日历显式使用 `Asia/Shanghai`；删除监控 v1、旧站点数据接口和公开站点原文弹窗，不保留兼容。
- 测试仅独立测试库和本地假服务，采集、模型和推送安全阀保持关闭；不自动真实调用或部署。

## 采集与识别

- 第三方查询负责主帖、自回复及回复他人的筛选，本地解析、去重、保存返回结果，不重复按回复目标账号过滤；目标账号缺失不丢弃帖子。
- 引用对象保存为可复用帖子并保留自身父帖关系。上下文先从本轮响应和当前监控帖子补齐，仍缺失时按明确父帖或引用 ID 付费补采，经过预算、回执与采集安全阀；不抓整个评论区。外部作者及窗口外材料只作上下文，不自动生成官方动作。
- 按真实回复、引用关系分组，一组一次模型识别；待处理帖子与只读上下文分开，已处理帖子不自动重识别。每个动作逐帖核验证据，组内事务保存，过期结果不得覆盖人工修改。
- 付费结果先存回执，写入失败复用 received 响应；计费未知不自动重发。所有采集与组处理持久完成才推进成功截止，明确歧义转人工，不将网络失败当作父帖不存在。
