# Grok 额度动态

本目录只保留 Grok 配置、识别与产品策略、时间策略和共享引擎的薄入口。

- 主信源为 `@bot` 与 `@grok`，两者均可独立提供官方事件依据；其他作者仅作上下文。
- 沿用适用产品和套餐。原帖未说明产品时，`@bot` 默认 Grok Bot，`@grok` 默认 Grok 普通额度；原文明示优先，套餐不推测。默认产品不得覆盖已有事件或人工字段。
- 启用 `direct_reset`、`reset_credit`、`bonus_credit`。普通限额调整、日常自动重置、API 赠金、政策解释和玩笑不生成事件。
- 产品及套餐冲突不能自动合并；跨账号关联需要同一事件依据，歧义留人工复核。奖励可领取不表示个人到账。
- 时间只按原文明示的时区或相对时长换算，缺时间保留原话，不预测。
- 共用 `MONITOR_MODEL`、供应商凭据、回执、预算和安全阀。通用实现位于 `../reset-monitor/`，不复制业务代码或新建表。
- 测试只连接本地假服务，样本注明模拟。真实初始化由使用者指定有限起止时间；不自动开启采集或推送。
- 首次最近 90 天真实初始化按已确认范围采集全部非回复帖和额度相关官方回复。范围策略仅在本次初始化进程提供，保留已经保存的范围外帖子及筛选依据，不调用模型处理日常自动回复。
- 首次有限范围初始化使用共享引擎的分页断点，以相同时间范围、账号顺序和筛选版本重新执行时续采；已完成账号和查询不再次请求。正常增量采集与每日查漏沿用原检查点规则。
- 额度回复的供应商查询必须覆盖本地接受规则，查询长度超限时拆分；旧查询断点保留，新增范围作为额外补采查询，只有新旧查询全部完成才算覆盖完整。仅采集入口默认不调用正式识别或补采上下文，历史本机续采命令同样遵守；修复及测试不代表授权继续付费采集。
