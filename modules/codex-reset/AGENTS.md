# Codex 重置监控模块

本目录保留 Codex 配置、产品语义、薄入口、回归测试及不可改写的历史迁移。通用代码与新增迁移放 `../reset-monitor/`，执行该目录的 `AGENTS.md` 和根目录规则。

后台基础路径 `/admin/codex-reset` 分为“事件列表”和“帖子列表”两个 tab，默认事件列表，以 kind=events/posts 切换。只提供北京时间开始日期 from、结束日期 to 筛选（包含当天），各自分页，切换保留时间范围并清除页码。事件按最新来源时间筛选和排序，下方默认展开动作及来源；帖子列表包含已关联与未关联帖子，按发布时间筛选和排序。`/events/:id` 管理事件并复用列表时间线和弹框；帖子在列表弹框内管理，旧 `/posts/:id/review` 和独立 `/posts` 页面均不提供。

- 账号、默认产品、套餐和公开目录在 `site/reset-monitors.ts`，初始账号为 Tibo（`@thsottiaux`）；只有配置账号可提供官方承诺，其他作者仅作上下文。
- 统一启用 `direct_reset`、`reset_credit`、`bonus_credit`。重置卡与直接重置分开，额外消费额度与可兑换重置次数分开；API 赠金、日常自动重置、条件政策、解释、玩笑和模糊惊喜不生成事件。
- 同帖逐项判断动作；同一次重置的解释不新增事件，明确多轮重置分别保留。跨账号关联须有可核验的引用、回复关系或原帖链接，不按时间相近强行合并，目标不唯一转复核。
- 原文和随帖引用仅保存在帖子，运行识别直接读帖子；不存全文翻译，原文不进事件、动作、公开响应或审计。供应商原始响应仅留付费回执供计费及请求续处理。
- 帖子 processing_status 只表达识别进度：pending、processed、needs_attention、failed，保留 review_reason，不维护 manual。是否支持动作从 sources 判断；worker 只处理 pending，写入核验原始版本和 pending 状态。动作、来源和重排不改识别进度，明确完成帖子处理才设 processed 并清空原因，翻译只补文案。
- 事件状态与时间统一由动作推导，confirm 允许 sources=[] 且须明确生效时间，标题摘要说明人工核实或推定，其他动作必须有来源；不保存独立人工核实字段或判定元数据。人工确认使用原有动作流程，不提供核实结果或人工未生效暂停。模型只读取有来源的官方动作。动作使用 `announce`、`confirm`、`progress`、`amend`，多来源不重复统计，新事件从预告或确认开始。
- 三类事件共用状态与动作规则；有效 confirm 均为 completed，官方确认优先于无来源确认；新预告、计划修订、延期、取消可使旧无来源确认不再决定结果。领取关闭、到期、重开使用 progress，取消使用 amend 并设 invalidatesEvent=true，取消为业务终态，只能更正或删除错误取消动作后重算。正式关系只有事件包含动作、动作引用帖子，不维护独立绑定；sources只postId，sequence属于动作。范围只在事件保存，事件、动作、来源、顺序变更分开表达。为已有官方事实补来源不能更正共享事实；无来源确认获得官方证据时更新同一动作来源、标题摘要及实际时间并保持 ID，关联不明转复核。
- 事件只编辑类型、标题、摘要、范围及可见性，不直接改状态或时间。动作与来源更正先预览，提交必须有理由、版本核验并一次事务完成；受影响事件同步重算。没有账户回执核对入口或确认依据。
- 进展和确认不扩大既有范围，范围更正须有明确依据。奖励可领取不代表个人到账，奖励关闭、到期、重开须有活动动作依据。
- 时间与其他产品共用来源解析器和 Temporal：PST 固定 UTC−08:00，PT 按 America/Los_Angeles 夏令时规则；单个钟点不扩大成区间，不使用作者发放惯例。有来源确认无实际时间取确认来源发布时间；无来源确认必须填写明确时间，不能用创建时间补缺。
- 已撤回事件保留动作及来源、人工处理入口，恢复前校验有效动作；管理撤回与官方取消分开。人工翻译按编辑版本处理，worker 不覆盖新的人工修改。
- 事件列表通过弹框新增、编辑动作与来源，事件详情管理全部动作和顺序；帖子复核通过选择器创建事件、添加动作或补来源，不手写 ID。事件创建或范围更新、动作创建或更正、来源增删和顺序重排分组提交，不把事件类型或范围放入动作草稿。版本核验与锁仅限相关记录，无关事件变化不使表单失效；增删来源不改 sequence。
- 前端只通过 HTTP 读取 v2，监控 v1、旧站点数据接口和公开站点原文弹窗删除，不保留兼容。Agent、MCP、通知与 Webhook 使用同一动作投影。
- 服务端通过 server.ts 绑定共享实现，web/ 仅保留页面薄入口，不保留无消费者的 backend/ 转发别名；前端不得导入后端配置，不恢复模型榜或其他已移除功能。列表分页放在下方，显示总数和页数，关联候选独立分页查询。
- 真实调用使用回执、预算与安全阀；测试仅本地假服务及独立测试库。离线样本放 `.data/local-preview/`，不提交凭据或生产快照。只使用当前格式的维护工具，不自动部署或恢复付费运行。

## 采集与识别

- 第三方查询负责主帖、自回复及回复他人的筛选，本地解析、去重、保存返回结果，不重复按回复目标账号过滤；目标账号缺失不丢弃帖子。
- 引用对象保存为可复用帖子并保留自身父帖关系。上下文先从本轮响应和当前监控帖子补齐，仍缺失时按明确父帖或引用 ID 付费补采，经过预算、回执与采集安全阀；不抓整个评论区。外部作者及窗口外材料只作上下文，不自动生成官方动作。
- 按真实回复、引用关系分组，一组一次模型识别；待处理帖子与只读上下文分开，已处理帖子不自动重识别。每个动作逐帖核验证据，组内事务保存，过期结果不得覆盖人工修改。
- 付费结果先存回执，写入失败复用 received 响应；计费未知不自动重发。所有采集与组处理持久完成才推进成功截止，明确歧义转人工，不将网络失败当作父帖不存在。
