# 公共额度快照 v2

## 接口

| GET 路径 | platform |
| --- | --- |
| `/api/v2/codex-resets` | `codex` |
| `/api/v2/claude-resets` | `claude-code` |
| `/api/v2/grok-resets` | `grok` |

接口通过共享 publication 模块入口读取，完整返回 `schemaVersion: 2`、`generatedAt`、`sources`、`catalog`、`events`、`overview`、`statistics`、`history`、`calendar`。对象禁止额外字段。未知字段用 null、unknown 或空数组；不使用模拟数据。v1、网站页面、Agent 和 MCP 保持原有契约。

响应使用 JSON、60 秒缓存和 ETag；生成时间不参与 ETag，事件与派生统计参与。条件请求可返回 304，读取或契约校验失败返回 503。读请求不写数据库、不调用采集或模型。

规范来源为 when-reset 的 `docs/api/fields.md`、`docs/api/openapi.json` 及 `src/lib/news-hot/contracts.ts`；本仓库的 `modules/reset-monitor/public-v2.ts` 实现同一契约。不能通过放宽校验解决数据缺口。

## 核验数据

核验字段保存在现有事件的 `presentation.publicV2`，不新增表或列。首次发布时间独立保存，修改内容或关联不改变它。七语言为 en、zh、zh-Hant、ja、ko、ru、es；不存在的事实保持 null，不能把原帖当摘要或把简体复制为繁体。通用标题和专有名称由七语言模板提供。

每次核验绑定事件事实、关联与来源的内容摘要；事实变化后旧文本、范围和时间失效，回到保守投影，再通过整理命令补齐。首次发布时间不因失效漂移。公开范围遵守既有撤回规则。

来源包含配置账号和公开事件引用的原帖，稳定 ID 按账号或帖子 ID 生成。事件优先列出预告原帖。产品、套餐和额度窗口目录属于各自平台；未说明的限制不补齐，不从产品名称推断用户范围。

直接重置与重置卡的完成、奖励开放只认明确官方依据；个人账户核验不代表全体用户。时间经过不修改事件状态。奖励关闭、到期或重新开放必须是针对整个活动的明确陈述；条件、个人账户情况、否定、问题和未来安排不改变状态。明确发生时间优先；官方确认完成或奖励开放但未给出发生时间时，使用关联中最早的官方确认帖发布时间作为公开时间节点，补全依据只保留在内部核验记录。首次预告、后续提醒、数据库修改时间和个人账户核验时间不能充当该节点；同一活动的后续确认不移动节点。没有官方确认帖时仍保留未知。事件首次发布时间 publishedAt 独立保存，不因补充确认时间而改变。

预告、领取截止和奖励到期分别保存，不使用完成公告发布时间充当这些字段。明确月日可自动补全年份：优先原文明示年份，否则根据同一活动首次公告的来源日期确定下一次对应月日，处理十二月至一月的跨年；后续提醒沿用活动起点，不按当前日期滚动。时区优先取时间原话，其次同帖，再次同一活动中的明示时区；均未说明时使用数据库原帖时间戳的统一归档时区 UTC。内部核验记录保留补全依据；标题、摘要、详情、范围和奖励说明只提供业务内容，不注明来源、依据或推断过程。

例如 2026 年 9 月发布活动、原文给出 `Oct 7 at 11:59pm PT` 和 `expires Nov 4`，领取截止解析为 `2026-10-08T06:59:00Z`，到期解析为 `{kind:"date",date:"2026-11-04",timeZone:"America/Los_Angeles"}`；不虚构到期时分。同日简写提醒保留既有精确时分；明确修改日期或时刻时替换，明确撤掉时分时保留新的日期精度。显式 ET、EST、EDT、PT、PST、PDT、有效 IANA 时区及 UTC/GMT 偏移完整解析；无法识别或相互冲突时保留未知，不按缺失时区处理。next/last 星期使用严格下一次／上一次该星期，同星期至少相隔七天。明确区间保留 range（含跨午夜与两端日期），不将起点伪装成精确发生时刻或纳入典型间隔。真实存在的日期和时间才能补全，错误日期或纯粹模糊描述仍列入缺口。后端在统一投影中使用已保存原文解析，读请求不调用模型；前端只读取结果。

## 派生数据

- 30 天统计采用北京时间含当天的最近 30 个自然日，按明确发生时间或官方完成／开放公告时间节点计数，不宣称外部历史完整。近期已确认但没有可核验时间节点的记录令对应计数为 null，不能把它们忽略后显示成零。
- 典型间隔使用最近 90 天官方已完成直接重置的精确时间节点（明确发生时刻或官方完成公告发布时间），取正间隔中位数，单位 day，sampleCount 为间隔数；没有有效间隔时为 null。
- 统计预告以最近完成事件的精确时间节点为锚点。使用锚点前 90 天至少三次记录，取正间隔中位数加到锚点上；失效阈值等于预测时刻。没有新事实时不随当前时间滚动延后，预测可能已经过期。
- 最新事件按首次发布时间确定；最近完成事件按发生时间排列，未知时回到首次发布时间，同值按稳定 ID 升序。重置卡与奖励不参与这两个引用。
- 历史包含全部可公开事件，按首次发布时间倒序、ID 升序排列。未知发生时间不移除记录，total 等于 eventIds 长度。
- 日历使用同一事件时间节点与已核验的奖励里程碑。精确标记的 UTC 锚点日期前后各扩一天，纯日期保留原日期；未知时间不生成标记。

## 整理与应用

使用 `node --env-file-if-exists=.env modules/reset-monitor/scripts/public-v2.ts`，支持 `export --output <文件>`、`preview --input <核验文件> --output <新目录>`、`apply --input <核验文件> --output <新目录> --reason <理由>`。导出包括三个监控的现有帖子、事件、关联、审计与内容摘要。核验文件保留导出版本并填写各事件 publicV2；预览生成逐项差异、缺口与三个快照。输出文件或目录必须尚不存在，避免覆盖核验材料。

apply 只写已有 JSON 字段并记录审计；核验版本不匹配时中止，整批事务提交，不部分保存。应用事务显式使用 read write，可在连接默认只读时执行已授权的写回，不修改连接默认设置。不会请求采集、模型或发送通知。正式数据先备份、在独立测试库演练，待使用者确认具体差异后才写回；公开部署另行确认。

真实快照、核验输入和执行结果放 `.data/local-preview/reset-monitor-v2/`，不提交运营快照或凭据。测试只使用独立 `_test` / `_ci` 数据库与本地假服务。

## 增量处理

本站采用 automatic_incremental。仅处理切换后新存的帖子，沿现有采集检查点前进，不重跑历史材料或每日历史查漏。识别接受的新建、确认、更正及关联事件在保存事实的同一事务内登记待补全状态，使用现有 monitor 模型基于全部关联原文生成七语言业务内容。与新帖关联的旧事件也会刷新，已有且证据未变的核验信息跳过。

自动补全沿用严格契约、七语言要求、平台目录和原文引文校验。模型不能改变事件类型、业务状态、事件 ID 或首次发布时间；代码自动补全年份和时区并保留内部依据。不明确的事实保持未知。事实变更后旧补充信息即时失效；读取接口始终不调用模型。

待处理、错误及回执状态保存在现有 monitor_state；成功时补充字段、审计和模型回执在同一事务内提交，并清除待处理状态。上下文按新帖、识别按固定输入、补全按事件证据版本使用持久请求标识；模型返回但保存中断时下轮复用相同输入的响应；计费未知阻止自动重发，无效响应或明确拒绝按现有回执规则处理。处理失败不推进本轮采集检查点，不重识别已提交的帖子。失效的已核验旧事件可被 worker 发现并重新补齐；人工修改或关联变化导致版本不符时禁止覆盖。

上线须单独授权部署及真实模型调用。安全阀关闭时不发外部请求、不推进自动处理成功检查点。
