# 公共额度接口 v2

## 接口

| GET 路径 | 响应 |
| --- | --- |
| /api/v2/overview | schemaVersion、generatedAt、platforms |
| /api/v2/codex-resets | list、pagination |
| /api/v2/claude-resets | list、pagination |
| /api/v2/grok-resets | list、pagination |

总览每个平台包含 platform、sources、catalog、statistics、predictedResetTime、announcedResetTime、resetTime。来源覆盖全部公开事件引用账号。最近事件包含直接重置、重置卡和奖励额度，按 time 倒序、ID 升序取第一条：状态 announced 时只返回 announcedResetTime，其他状态只返回 resetTime，无事件两者均 null。三个时间字段是 ISO 时间字符串或 null，不返回事件对象。

predictedResetTime 以最近已完成直接重置的精确时间为锚点，取此前 90 天至少三次精确已完成记录的正间隔中位数推算。样本不足 null，预测不晚于当前时刻则返回北京时间明天的 YYYY-MM-DD，每天重算，不修改事实。统计覆盖全部公开事件，不受列表筛选影响。

列表顶层只有 list 与 pagination:{limit,total,hasMore,nextCursor}。事件保留完整 updates，不返回 bonusCredit 字段（也不返回 null）。奖励事件仍以 type=bonus_credit 返回标题、摘要、范围、状态、时间与更新；内部核验和存储继续保留奖励详情。目录与账号元数据从总览读取，不返回旧 overview/history/calendar 或完整快照。

查询支持 from、to、timeZone、limit、cursor。日期、timeZone 和 limit 去除首尾空白，空值视为未传。timeZone 默认 UTC，接受 Asia/Shanghai、America/Los_Angeles 等 IANA 命名时区，不接受数值偏移或无效时区。日期仅 YYYY-MM-DD 且含两端；全空取所选时区本月月初至月末，单边补该日期所在月另一边界。最多六个自然月，非法或颠倒范围返回 400，不截断。精确时间按所选时区的 from 当天零点至 to 次日零点左闭右开筛选，按日历推进边界以处理夏令时，区间取起点。纯日期直接按日期比较，不随查询时区移动。

例如 `/api/v2/codex-resets?from=2026-10-01&to=2026-10-31&timeZone=America%2FLos_Angeles` 查询洛杉矶当地十月。查询时区只影响日期筛选和默认月份，不改变事件时间、排序或总览统计。事件按 time 倒序、ID 升序排列；纯日期仅为排序按 UTC 零点比较，不表示实际发生在该时刻。

limit 空值返回范围内全部，响应 limit=null、hasMore=false、nextCursor=null；否则为 1–100 整数并启用游标。total 为筛选后的全部事件数。游标绑定平台、实际日期、规范化时区和 limit，记录末条事件时间与 ID；空、非法、不匹配或无有效 limit 时返回 400，切换时区需从第一页重新获取。未知或重复参数拒绝。分页读取实时数据，不保存分页快照，数据变化后从第一页重新获取完整结果。

所有接口经 publication 读取层输出；匿名 JSON、CORS、60 秒缓存和 ETag/304。ETag 排除 generatedAt，包含实际响应和有效日期范围，以处理跨日、跨月和预测过期。读取不写库、不采集、不调用模型；失败 503。

规范来源为 when-reset 的 docs/api/fields.md、docs/api/openapi.json 和 src/lib/news-hot/v2-contracts.ts。消费端页面和原 HTTP 客户端本次不改，接入另行适配，V1 契约保持不变。

## 核验数据

核验字段保存在现有事件的 `presentation.publicV2`，不新增表或列。首次发布时间独立保存，修改内容或关联不改变它。七语言为 en、zh、zh-Hant、ja、ko、ru、es；不存在的事实保持 null，不能把原帖当摘要或把简体复制为繁体。通用标题和专有名称由七语言模板提供。

每次核验绑定事件事实、关联与来源的内容摘要；事实变化后旧文本、范围和时间失效，回到保守投影，再通过整理命令补齐。首次发布时间不因失效漂移。公开范围遵守既有撤回规则。

`sources` 只包含配置账号及公开事件关联的历史账号，使用账号名称与主页，不按帖子重复建立来源。账号 ID 使用小写 handle 生成的 `x-account:<handle>`，同一账号不区分大小写，配置中的显示名优先保留；没有事件时也返回全部配置账号。

每个事件返回非空 `updates`，完整列出该事件已接受的业务更新，不包含顶层 `primarySource` 或 `sourceIds`。每条更新为 `{id,action,publishedAt,summary,source:{sourceId,url}}`：id 使用原帖 ID，在同一事件内唯一；action 为 announce、confirm、progress、amend、withdraw；publishedAt 为该条原帖的实际发布时间；summary 为本次更新的七语言业务摘要或 null，不复制整段原帖、不复用事件总摘要。sourceId 引用总览对应平台 sources 的账号，url 使用该更新已存原帖地址。引用缺失或 URL 不合法时返回 503，不以主页或拼接地址补位。

更新按 publishedAt 倒序、ID 升序。顶层 status/time/summary 表示事件当前结果，updates.action 表示每次更新做了什么，updates.publishedAt 不用预计执行时间替代。同一事件有多条更新仍只算一次重置或发放。来源链接使用对应更新的 source；事件列表可用首条更新来源，并可展开完整时间线访问各条来源。

核验包可保存 `updateSummaries: [{postId,summary}]`，一旦提供就必须完整覆盖全部已接受业务更新，不重复、不包含其他帖子。每条摘要七语言齐全，且 evidence 中有对应原帖的逐字引文；更新 ID、action、时间与地址仍由已存关联和原帖投影。未补摘要或内容依据失效时只返回 null；自动增量补全必须同时生成这些摘要，不复用事件总摘要。

账号主页和更新原帖地址共用严格 HTTP(S) URL 校验：必须显式包含协议和主机，不允许用户凭据、空白或反斜杠；路径、查询或片段内的 `@` 合法。两种地址可以来自不同域名。产品、套餐和额度窗口目录属于各自平台。

本站 Codex、Claude 的 `catalog.quotaWindows` 包含 `five-hour`（五小时额度）、`weekly`（周额度）和 `monthly`（月额度），均提供七语言名称。Grok 保留五小时和周额度目录。目录描述可用的窗口代码，不表示每个事件都重置这些窗口；`scope.quotaWindowCodes` 仍只列原文明确涉及的窗口。

用户范围没有明确说明时，`scope.type` 默认 `all_users`；已保存的 `unknown` 在公开投影中使用这一默认值。明确的 `paid_users`、`selected_users` 及产品、套餐、额度窗口保留。公开 `scope.note` 必须非空并提供七语言：`all_users` 固定显示“所有用户”，`paid_users` 固定显示“付费用户”，`selected_users` 显示有依据的具体用户条件，条件缺失或语言不全则校验失败。此规则统一应用于已有事件投影和后续补全，不要求重识别或写回历史数据。`all_users` 表示已有产品、套餐等限制范围内的全部用户，不意味着所有产品或套餐；未说明的其他维度仍为空数组，不从名称猜测限制。

直接重置与重置卡的完成、奖励开放只认明确官方依据；个人账户核验不代表全体用户。时间经过不修改事件状态。奖励关闭、到期或重新开放必须是针对整个活动的明确陈述；条件、个人账户情况、否定、问题和未来安排不改变状态。

事件不包含 `announcement` 或 `details`；严格契约拒绝这两个字段，文案只保留标题和摘要。`type` 只区分直接重置、重置卡和奖励，`status: announced` 表示预告。同一事件确认后更新状态和时间，不新增预告类型、不把预告与确认拆成两条事件。

事件的 `time` 是 ISO 8601 字符串：精确时间如 `2026-10-03T04:26:28Z`，仅日期如 `2026-10-03`，时间区间如 `2026-10-03T04:00:00Z/2026-10-03T05:00:00Z`；不接受对象、null 或 unknown。纯日期不补午夜，区间保留两端。预告状态优先保存明确计划时间，确认后使用明确实际时间／日期；缺失时使用同一事件最后一条已接受业务更新原帖的发布时间，不使用数据库编辑时间、当前时间或无关帖。默认时间不宣称实际执行发生于该时刻。首次发布时间与主帖不变。

公开 time 的精确时间和区间两端统一输出 UTC（Z），读取已有带偏移时间时换算为同一时刻，不修改已存核验信息。纯日期保留原值，不补时分或时区。总览引用事件的 announcedResetTime/resetTime 使用同一 UTC 输出。

自动生成和人工核验导入的 time 在写入前复用同一 UTC 归一化函数，精确时间与区间两端以 Z 保存，保留小数秒精度，纯日期不变。导入预览展示实际将保存的值，应用审计中的 after 与入库值一致；导入输入中的偏移形式在校验后换算，不改写原帖、来源时区依据或未提交的历史记录，无需数据库迁移。

内部核验信息使用可选 `timeBasis: source|latest_update` 区分明确来源时间与默认时间，不进入公开响应。`source` 对预告表示计划时间，对确认表示实际时间／日期；`latest_update` 随同一事件的有效更新变化。奖励领取截止、到期和内部来源解析继续保留结构化时间精度。升级时先备份、把已预告事件的明确计划时间折入 time、其他事件规范为实际或最近更新时间，移除已存 announcement 与 details，再启动新版 API／worker；消费端契约同步更新，不保留旧格式读取分支。

领取截止和奖励到期独立保存，不使用完成公告发布时间充当这些字段。明确月日可自动补全年份：优先原文明示年份，否则根据同一活动首次公告的来源日期确定下一次对应月日，处理十二月至一月的跨年；后续提醒沿用活动起点，不按当前日期滚动。时区优先取时间原话，其次同帖，再次同一活动中的明示时区；均未说明时使用数据库原帖时间戳的统一归档时区 UTC。内部核验记录保留补全依据；标题、摘要、范围和奖励说明只提供业务内容，不注明来源、依据或推断过程。

例如 2026 年 9 月发布活动、原文给出 `Oct 7 at 11:59pm PT` 和 `expires Nov 4`，领取截止解析为 `2026-10-08T06:59:00Z`，到期解析为 `{kind:"date",date:"2026-11-04",timeZone:"America/Los_Angeles"}`；不虚构到期时分。同日简写提醒保留既有精确时分；明确修改日期或时刻时替换，明确撤掉时分时保留新的日期精度。显式 ET、EST、EDT、PT、PST、PDT、有效 IANA 时区及 UTC/GMT 偏移完整解析；无法识别或相互冲突时保留未知，不按缺失时区处理。next/last 星期使用严格下一次／上一次该星期，同星期至少相隔七天。明确区间保留 range（含跨午夜与两端日期），不将起点伪装成精确发生时刻或纳入典型间隔。真实存在的日期和时间才能补全，错误日期或纯粹模糊描述仍列入缺口。后端在统一投影中使用已保存原文解析，读请求不调用模型；前端只读取结果。

## 派生数据

30 天统计采用北京时间含当天的最近 30 个自然日。典型间隔使用最近 90 天官方已完成直接重置的精确时间，取正间隔中位数；不将日期或区间伪装成精确时刻。预测只在读取层计算，不交给识别或补全模型。

## 整理与应用

使用 `node --env-file-if-exists=.env modules/reset-monitor/scripts/public-v2.ts`，支持 `export --output <文件>`、`preview --input <核验文件> --output <新目录>`、`apply --input <核验文件> --output <新目录> --reason <理由>`。导出包括三个监控的现有帖子、事件、关联、审计与内容摘要。核验文件保留导出版本并填写各事件 publicV2；预览生成逐项差异、缺口与三个快照。输出文件或目录必须尚不存在，避免覆盖核验材料。

apply 只写已有 JSON 字段并记录审计；核验版本不匹配时中止，整批事务提交，不部分保存。应用事务显式使用 read write，可在连接默认只读时执行已授权的写回，不修改连接默认设置。不会请求采集、模型或发送通知。正式数据先备份、在独立测试库演练，待使用者确认具体差异后才写回；公开部署另行确认。

真实快照、核验输入和执行结果放 `.data/local-preview/reset-monitor-v2/`，不提交运营快照或凭据。测试只使用独立 `_test` / `_ci` 数据库与本地假服务。

## 增量处理

本站采用 automatic_incremental。仅处理切换后新存的帖子，沿现有采集检查点前进，不重跑历史材料或每日历史查漏。识别接受的新建、确认、更正及关联事件在保存事实的同一事务内登记待补全状态，使用现有 monitor 模型基于全部关联原文生成七语言业务内容。与新帖关联的旧事件也会刷新，已有且证据未变的核验信息跳过。

自动补全沿用严格契约、七语言要求、平台目录和原文引文校验。模型不能改变事件类型、业务状态、事件 ID 或首次发布时间；代码自动补全年份和时区并保留内部依据。用户范围和事件时间使用上述默认规则，其他不明确的事实保持未知。事实变更后旧补充信息即时失效；读取接口始终不调用模型。

已接受事件中的明确用户类型、产品、套餐及额度窗口由代码约束，补全结果不得丢失或扩大适用范围；无法映射的明确限制转待复核。模型提示词不能代替这一步校验。无效答复在拒绝回执和 needs_review 状态一并提交前保持 received；数据库写入失败或进程中断后复用已保存响应，不重复付费。

待处理、问题及回执状态保存在现有 monitor_state；成功时补充字段、审计和模型回执在同一事务内提交，并清除待处理状态。采集、上下文和识别成功即可推进本轮检查点。事件事实已提交后，七语言、引文、范围代码、时间证据或编辑版本校验未通过，仅将该事件的补充任务记为 needs_review，本轮结果携带 enrichmentPending 数量，不阻断其他事件或把整轮标为失败。公开仍使用严格契约：保留事件及七语言通用标题，未通过的补充内容不公开；未知字段保留 null 或 unknown。

上下文按新帖、识别按固定输入、补全按事件证据及编辑版本使用持久请求标识；模型返回但保存中断时下轮复用响应。相同版本的 needs_review 不自动反复购买；来源、事实或人工安排补全发生变化后可再次处理。回执保留无效响应的真实结果，不能把它伪装成有效输出。计费未知仍阻止自动重发，采集、识别、传输、预算或数据库持久化故障仍报错且不推进检查点，不重识别已提交帖子。失效的已核验旧事件可被 worker 发现；并发修改导致版本不符时禁止覆盖，待新版本重新补全。

上线须单独授权部署及真实模型调用。安全阀关闭时不发外部请求、不推进自动处理成功检查点。
