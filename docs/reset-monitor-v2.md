# 公共额度接口 v2

## 无来源确认

帖子进入待人工处理时，已经通过识别结构校验的帖子标题和摘要仍保存到来源记录，保留七语言文案、识别回执及待处理原因；动作事实或关联未通过校验时不创建事件动作。文本保存与状态更新在同一事务核验原始版本及 pending 状态，不能覆盖后续人工编辑。没有有效识别文本时保留已有文案，不伪造摘要，也不为待处理展示额外购买模型调用。

后台帖子列表提供创建、编辑和关联管理弹框。人工创建保存配置作者、真实发布时间、原帖链接、原文和中文标题摘要，标记已处理，不触发识别、事件、动作或 Webhook；帖子明确加入动作来源后才形成公开关系。编辑已有帖子仅修改标题摘要，来源信息和识别状态只读，保留原有关联、处理说明和过滤结果。原文仅管理员可读，不进入公开接口或审计。创建不覆盖重复来源；编辑须核验帖子版本，冲突重新读取。帖子弹框不要求复核理由，服务端自动记录创建或编辑审计。

帖子列表的“关联事件/管理关联”弹框每次读取最新复核数据，固定当前帖子为来源。主弹框只按事件分组展示关联，不显示顶部帖子信息；关联已有事件和新建事件按钮位于当前关联标题右侧，配置操作进入独立子弹框。子弹框只暂存草稿，支持多项变更及逐项撤销，主弹框底部取消、预览影响及预览后的保存统一处理；草稿变化使预览失效。可搜索已有事件，选择已有动作补来源或新增动作；也可复用事件字段及动作表单，将新事件、首个动作和来源在一次预览及事务中保存。取消不留下空事件，失败保留输入，版本冲突须重新读取后预览。普通补来源不修改事实，当前无来源确认补官方证据时允许同步更正标题、摘要和实际时间，保留动作 ID。管理关联可以移除来源，最后来源移除预览明确显示动作删除及事件影响。从帖子新建事件并关联当前帖的有效首个动作，视为完成该帖复核，预览展示后同一事务设 processed 并清空原因；仅补已有动作来源、编辑动作或移除来源仍不改变识别进度。服务端为省略的理由记录“后台帖子关联”。成功后刷新当前列表并保留 tab、日期、筛选和页码；“无关联”筛选中已完成关联的记录移出。动作变更沿用翻译、公开投影及 Webhook 流程，无新增接口或数据字段。

后台可独立创建事件信息，创建与编辑共用类型、标题、摘要和影响范围字段；不附带动作或来源。无有效初始动作的事件仅后台可见，不返回到公开 v2、不参与统计或 Webhook。管理员在列表添加首个有效预告或确认后，事件才进入公开流程；沿用文案完整性与翻译要求，准备完成后发送首次 created 通知，历史通知基线不能吞掉新草稿的首次动作通知。

人工创建使用各平台 `POST {adminApiPath}/events`，只接受 `{type,title,summary,scope}`，中文标题必填；摘要和范围可为空，事件 ID 与创建时间由服务端生成。接口沿用管理员与 CSRF 校验，成功返回 201 及事件 ID、版本和创建时间。不接受客户端状态、业务时间、动作或来源。创建成功后进入后台事件列表首页，使用卡片“添加动作”继续完善，公开 v2 结构不变。

事件结果统一由动作推导。`confirm` 允许 `sources=[]`，用于人工核实已生效或到时推定，必须保存明确生效时间；标题或摘要写明“人工核实已生效”或“已到预告时间”。其他动作仍必须有来源。不新增 `method`、`outcome`、`basisVersion`，不返回 `confirmation` 或总览 `resetConfirmation`，不解析标题摘要来判断业务规则。动作来源为空表示没有关联官方帖子，不能视作官方证据。

管理员通过原有添加、编辑动作流程填写明确实际时间和文案，保留预览、版本校验、事务及审计，事件动作弹框不要求手填理由，服务端为省略的理由记录操作说明。没有独立“核实结果”流程、`manual_verification` 字段或人工未生效暂停能力。后续采到官方确认时，补充当前无来源确认的 `sources`、标题、摘要和实际时间，保持动作 ID，不增加同一事件的统计次数。

独立分钟任务仅在事件官方事实仍为预告、有明确计划时间且没有取消或待核实来源时持久保存无来源确认。精确时间到点、日期按北京时间次日零点、区间按末端触发；发帖时间不能代替计划时间，缺明确时间不推定。读页面和接口不写库、不临时拼接动作，结果最多在下一分钟检查后出现，并受最长 60 秒缓存影响。首次启用先生成历史到期预告的确认，再建立通知基线，不补历史通知；之后沿用 Webhook 指纹、修订号和投递去重。

官方确认优先于无来源确认。新预告、明确计划时间修订、延期、取消按动作顺序使旧无来源确认不再决定当前结果，保留动作和审计历史。官方明确延期且时间待定时记 progress，暂停旧预告推定；有明确新计划的预告记 announce，使进行中事件重新进入预告并按新时间判断。普通 amend 不猜测延期。模型候选的状态、时间、默认标题及动作仅来自有来源的官方事实。

Codex、Claude、Grok 共用“帖子提供来源、动作记录事实、事件聚合结果”的模型。站点、API、Agent、MCP、飞书与 Webhook 均读取 publication 的 v2 投影；读取不写库、不采集、不调用模型。监控不提供 v1 或旧站点快照、版本轮询、按日数据接口，不保留兼容模式；新闻网站其他 v1 接口不受影响。

本站公开接口版本为 5.0.0，监控路径与 schemaVersion 保持 v2。三类事件共用四种动作和四种状态，动作必填 invalidatesEvent；总览允许预告时间与最近确认时间同时存在。严格客户端须同步接受无来源 confirm，并移除独立判定元数据；消费端按本契约直接读取完整 updates。

## 接口与查询

| GET 路径 | 响应 |
| --- | --- |
| `/api/v2/overview` | `schemaVersion`、`generatedAt`、`platforms` |
| `/api/v2/codex-resets` | `list`、`pagination` |
| `/api/v2/claude-resets` | `list`、`pagination` |
| `/api/v2/grok-resets` | `list`、`pagination` |
| `/api/v2/agent/codex-resets`、`/api/v2/agent/claude-resets`、`/api/v2/agent/grok-resets` | 基于同一 v2 投影的 Agent Markdown |

`/openapi-v2.json` 提供由共享 Zod 契约生成的静态 OpenAPI，生成命令为 `node modules/reset-monitor/scripts/openapi.ts`，文件位于 `site/public/openapi-v2.json`。契约变化须同时重新生成并核验。`/openapi-v1.json` 仅移除监控路径及无人引用的监控专属 schema，其他新闻接口保持。

匿名 JSON、CORS、60 秒缓存、ETag/304；失败返回 503。ETag 排除 `generatedAt`，包含实际响应与有效日期范围，跨日、跨月及预测过期后重新计算。四类通用动作与来源数组契约使用新的 API 缓存版本，旧响应与旧游标失效；发布时重新生成 OpenAPI，消费端直接使用新枚举，不保留旧动作结果格式。

列表顶层只有 `list` 与 `pagination:{limit,total,hasMore,nextCursor}`。查询支持 `from`、`to`、`timeZone`、`limit`、`cursor`；未知或重复参数拒绝。日期、时区和 limit 去除首尾空白，空值视为未传。

- 日期仅接受 `YYYY-MM-DD` 且包含两端。全空查询所选时区本月；单边补该日期所在月另一边界；最多六个自然月，非法或颠倒范围返回 400，不截断。
- `timeZone` 接受有效 IANA 命名时区，默认 UTC，不接受数值偏移。站点月历和按日历史显式传 `Asia/Shanghai`。
- 精确时间使用当地 `from` 零点至 `to` 次日零点左闭右开筛选，按日历计算边界以处理夏令时；区间取起点。纯日期直接比较，不随查询时区移动。
- `limit` 空值返回范围内全部，响应 `limit=null,hasMore=false,nextCursor=null`；否则接受 1–100 整数并启用游标。`total` 是筛选后的事件总数。
- 游标绑定平台、有效日期、规范化时区和 limit，记录末条事件时间和 ID；无效、不匹配或没有有效 limit 时返回 400。切换筛选或数据变化后从第一页读取，不保存分页快照。

事件按 `time` 倒序、ID 升序；区间取起点，纯日期仅为排序按 UTC 零点比较，不表示实际发生时刻。查询时区不改变事件时间、排序或总览统计。

## 事件、动作与来源

事件保留 ID、类型、七语言标题和摘要、结构化影响范围、当前状态和时间。所有出口使用同一 v2 形状，不返回原文、`details`、`announcement`、`primarySource`、`sourceIds` 或 `bonusCredit`（包括 null）；奖励事实由标题摘要、范围和动作表达。类型为 `direct_reset`、`reset_credit`、`bonus_credit`，预告用 `status: announced` 表达，不是单独事件类型。

`updates` 非空，返回动作而非帖子：

```text
updates[]:
  id             稳定动作 ID
  action         announce | confirm | amend | progress
  invalidatesEvent  是否为使事件失效的取消修订，仅 amend 可为 true
  title          七语言标题
  summary        七语言摘要，未就绪时为 null
  time           动作业务时间：精确时间、日期或时间区间；未明确时为 null
  publishedAt    有来源时为最早有效来源发布时间；无来源确认时为动作创建时间
  sources[]:
    postId       帖子 ID
    sourceId     来源账号 ID
    url          已保存的原帖链接
```

一个动作只属于一个事件，一个帖子可支持多个动作，一个动作可由多个帖子支持。相同事实明确复用已有动作 ID 并补来源，不能根据标题摘要哈希自动合并；目标或事实是否重复不清楚时转复核。不同事实的进展和修订可分别建同类动作，不能只按类型合并。

动作内部 `sources` 只保存 `{postId}` 数组，不复制链接；同一来源不能重复且必须属于当前监控。动作属于一个事件，事件关联帖子由动作来源汇总，不保留独立绑定。动作以事件内 sequence 重放，增删来源不改变 sequence；公开仍从帖子解析全部 `{postId,sourceId,url}`，不暴露内部顺序。前后台动作时间线左侧显示 `updates.time`，未明确时显示“—”，不使用 `publishedAt` 代替业务时间；日期和区间不补造钟点。

只有 `confirm` 可返回 `sources=[]`；其他动作的来源数组非空。有来源时完整返回动作的全部原帖链接，按帖子发布时间、帖子 ID 排序。URL 使用已保存地址，不拼接、不以主页替代；引用缺失或 URL 不合法时失败。来源变化后动作 `publishedAt` 按最早有效来源重新计算；无来源确认使用动作创建时间，不能把创建时间当作实际生效时间。动作按 `publishedAt` 倒序、动作 ID 升序；同帖多动作不会冲突，多帖同动作不重复统计。`updates.title/summary` 表达该动作事实，不能复用事件总摘要或复制原文。

所有公开文本使用 en、zh、zh-Hant、ja、ko、ru、es 七语言，不把简体直接复制为繁体。人工编辑使旧翻译失效，worker 按编辑版本生成新翻译；未就绪时用安全通用标题，摘要为 null，不公开失效文案。模型不得覆盖人工原意或通过补全修改动作、状态和时间。

总览 `sources` 只列 `site/reset-monitors.ts` 配置账号，按账号去重，不从历史事件补充作者；历史动作的其他有效账号仍通过各自 `sources` 返回。账号 ID 为小写 handle 对应的 `x-account:<handle>`。来源主页和原帖地址接受严格 HTTP(S) URL：必须有协议与主机，不含用户凭据、空白或反斜杠；路径、查询和片段内的 `@` 合法，不要求主页与原帖同域。

## 状态与时间

API、站点、统计、Agent、MCP、通知和 Webhook 共用动作归并的事件状态与时间，包含有效无来源确认；模型只读取有来源动作推导的官方状态与时间。新事件须从有效预告或确认动作建立，无来源确认须有明确生效时间；没有初始动作的事件不能公开。

| 动作 | 对结果的影响 |
| --- | --- |
| `announce` | 初始已预告，新的预告使旧无来源确认失效，不覆盖有效官方确认 |
| `progress` | 未完成事件进入进行中，延期等进展使旧无来源确认不再决定结果，不覆盖有效官方确认 |
| `confirm` | 三类事件统一进入 completed；有来源表达官方确认，无来源表达人工核实或推定；奖励确认不代表个人到账 |
| `amend` | 修正业务事实；明确计划时间修订使旧无来源确认失效，不覆盖有效官方确认 |
| `amend` 且 `invalidatesEvent=true` | 官方明确取消，事件为 cancelled，保留历史但退出总览时间、次数和间隔统计 |

业务取消是终态，新增预告、确认、进展或普通修订均不能恢复已取消事件，不提供取消后恢复动作。取消记录有误时，只能通过原有复核流程更正或删除该取消动作，再由剩余动作重算状态。三类事件共用动作规则。关闭领取、到期、重开作为 progress，不单独改变已官方确认状态；取消通过 amend 的 invalidatesEvent 明确标记，不从摘要文字猜测。个人账户情况、条件句、否定、提问及未来安排不能自动产生官方确认；奖励确认不代表个人领取或到账。时间经过仅在明确计划时间满足规则时由分钟任务生成无来源确认，不关联虚构帖子。管理撤回后的可见性恢复独立，不改变业务取消状态。

后台事件编辑只接受类型、标题、摘要、影响范围；事件页另设动作管理入口，新增、更正、来源和顺序调整须预览、相关记录版本核验及单事务提交；事件动作管理可省略理由，由服务端自动记录操作说明，涉及帖子文案、识别或保留操作的旧复核仍须理由。帖子关联弹框用选择器创建事件、添加动作或补来源，无单独绑定与手填 ID。移除最后有效来源后重算，没有有效初始动作停止公开，并提示核对范围。

事件“编辑”表单不要求填写原因。标题、摘要和影响范围说明用普通中文输入，范围的产品、套餐和周期代码保留；保存说明时只替换 `scope.note`，无需编辑 JSON。事件摘要直接返回保存值，清空后保持 null，不使用动作摘要补回，也不保存人工编辑标记。事件、动作和帖子创建或编辑保存后，各平台独立 worker 分钟任务检查缺失语言，使用已配置的监控模型补全。帖子四种识别进度 pending、processed、needs_attention、failed 都可补齐标题摘要，不要求先关联动作或完成识别。模型只读取保存的展示字段，已有语言原样保留，标题摘要或范围说明的空值保持为空；翻译绑定记录版本，过期响应不能覆盖后续编辑。失败版本不反复购买，新编辑产生新版本后重新判断。任务只受 `MODEL_CALLS_ENABLED` 控制，关闭采集不影响翻译；开发环境经用户授权后仅在 worker 进程开启模型调用，采集、识别及真实推送保持关闭，API 和页面读取不触发翻译。模型调用关闭时保留待处理文案，不进行外部调用。

`time` 是非空 ISO 8601 字符串，保留精确时间、纯日期或起止区间，例如 `2026-10-03T04:26:28Z`、`2026-10-03`、`2026-10-03T04:00:00Z/2026-10-03T05:00:00Z`。精确时间和区间两端统一 UTC（Z），纯日期不补午夜，不使用对象、null 或 unknown。

- 预告取明确计划时间，否则取有效预告动作发布时间。
- 有来源确认取实际生效时间或日期，缺失时取确认来源发布时间；不沿用计划时间、后台编辑时间、账户核对时间或后续普通进展时间。无来源确认必须保存明确时间，人工填写核实的实际时间，推定采用明确计划时间，不使用动作创建时间补缺。
- 其他状态取有依据的明确业务时间，否则取最近有效动作发布时间。
- 保留首次发布时间，重复采集和文案编辑不改变业务时间。领取截止和奖励到期独立，不充当重置生效时间。

时间解析在 worker 校验结构化事实时由统一解析器和 Temporal 完成，不在读请求中依赖业务表原文，不使用作者预测或发放惯例。PST 固定 UTC−08:00，PT 按 America/Los_Angeles 夏令时规则。明示年份和时区优先；缺年份根据同一活动首次公告日期确定并处理跨年，不使用当前年份或随提醒滚动。缺时区依次取同帖、同活动明确时区，否则使用原帖时间戳的统一归档时区 UTC。显式冲突或无法识别的时区保持待复核，不能当作缺失。纯日期保留精度；同日简写提醒不抹掉已知时分，明确修订才替换；next/last 星期保留相对周语义，明确区间不伪装成精确发生时刻。

## 总览、范围与派生数据

总览每个平台包含 `platform`、`sources`、`catalog`、`statistics`、`predictedResetTime`、`announcedResetTime`、`resetTime`，不返回独立确认依据字段。失效事件保留历史但退出总览与统计。最新有效事件按事件时间倒序、ID 升序确定，处于 announced 时仍返回预告时间。resetTime 独立取全部有效确认中最近一次生效时间；没有有效结果时为 null。新事件的预告不清空其他事件已有结果；同一事件的新预告可使旧无来源确认失效。官方确认无明确实际时间取其最早有效来源发布时间，人工确认必须填写实际时间，推定只采用明确计划时间；不以后台操作时间代替。

`statistics.typicalInterval` 使用此前 90 天三类有效事件的精确生效时间，含有来源与无来源确认，每个事件只计算一次；相邻正间隔取中位数，零间隔排除，不足时为 null。日期及区间不充当精确间隔样本。`predictedResetTime` 为 resetTime 加 typicalInterval，任一不足时为 null。精确时间保留时间戳、区间两端同步平移、纯日期保留精度；预测起始日期按北京时间比较，早于今天返回今天，当天不因时分已过而提前显示明天。预测不落库，不是官方事实。30 天统计按北京时间含当天最近 30 个自然日，以三类有效结果的生效日期分别计数，不受列表筛选或来源数影响；取消、撤回或不再有有效确认的事件移出统计。

影响范围只保存在事件 `scope`。事件创建或修改、动作创建或更正、来源增删、动作重排是分开的事务指令，不把 eventScope 嵌在动作草稿。补来源不得改变既有事实或范围；移除最后来源时提示核对范围，不猜测历史范围。摘要描述事实变化，但程序不从摘要推导状态或范围。

历史或人工事件的 `scope=null` 仍按默认 `all_users` 投影；新识别缺少可核验用户范围时使用 `unknown`，除非唯一关联事件提供已接受范围。明确的 `paid_users`、`selected_users`、`unknown`、产品、套餐和额度窗口原样保留。`scope.note` 使用七语言简洁标签；多个付费套餐概括为“付费用户”，单一套餐保留名称。付费标签不追加注册或升级截止时间、领取条件、周期、受影响人数等细节，具体条件保留在七语言摘要和原始证据中，特定用户的条件也可在动作摘要核验。`all_users` 指已有产品、套餐限制内的全部用户，补全不能丢失、扩大或替换已接受限制。

明确动作不因范围目录映射不全而拒绝关联。用户范围无法核实时使用 `scope.type=unknown`，中文说明标为“unknown 所有用户”；产品无法完整映射时不猜测默认产品，`productCodes=[]`，中文说明标为“unknown 所有产品”。两个维度均未知时可组合为“unknown 所有用户 · unknown 所有产品”。这些标签表示未知维度未限定查询范围，不表示官方已确认覆盖全部用户或产品。已核实的套餐、周期及其他维度代码继续保留，无法表达的实际产品、资格和周期限制保留在七语言动作摘要与原文中；不能把 `hourly` 猜成 `five-hour`。空代码数组本身表示没有可用代码限制，不能单独推断“已知全部”或“未知”，须结合 `scope.type`、`scope.note` 和摘要。已有事件的唯一关联可继承已接受范围，普通补来源不能用 unknown 覆盖已知限制；明确事实冲突仍待复核。前后台、Agent、MCP 与 Webhook 保留同一范围信息，不新增字段、目录代码或接口版本。

固定范围标签（所有用户、付费用户、unknown 用户或产品及其组合）在只保存中文等部分语言时，可在公开投影中用共享标准译文补齐其余语言。所有已有非空语言必须与同一标准标签匹配；补齐不修改存储、scope.type 或目录代码，也不从标签推断事实。任意资格条件、相互冲突的部分译文，以及 selected_users 的不完整说明继续等待完整译文；读取页面和接口不调用模型。标题摘要仍沿用既有缺失文案的安全展示规则。

Codex、Claude 目录包含 `five-hour`、`weekly`、`monthly`，Grok 保留已有目录。目录是可用代码，事件只列来源明确涉及的范围，不自动添加月额度。奖励不计入重置次数。

## 存储、增量处理与整理

帖子保存来源、作者、发布时间、原帖链接、原文 text、随帖引用 quoted_post、七语言标题摘要及必要处理记录。后续识别直接读取帖子，不依赖采集回执；不保存原文全文翻译。原文和引用分开，引用不能代替外层帖子动作依据。原文仅后台管理员可读，不进入公开响应、事件、动作或业务审计。供应商原始响应仍仅在内部付费回执，保留计费和请求续处理。

帖子 processing_status 只表示识别进度：pending、processed、needs_attention、failed，保留 review_reason，不维护 manual。是否支持动作由 sources 推导，不用状态区分有无相关事实。worker 只处理 pending，写入成功、待人工处理和失败前核验输入原始版本及 pending 状态；过期任务不能覆盖人工处理。动作更正、补删来源和重排不改变帖子处理状态；帖子处理入口明确完成识别时设 processed 并清空原因；管理员从帖子新建事件并将当前帖关联到有效首个动作，也视为完成该帖人工复核，预览展示状态及原因变化，与事件和动作同一事务提交，保留前后状态和原因审计。仅补已有动作来源、编辑动作、移除来源不改变识别状态。翻译任务只补文案，不改识别状态。

采集按平台 collection 配置处理账号主帖及可选回复；主帖始终开启，includeReplies（回复他人）、includeSelfReplies（自回复）与 resetOnly 分别控制；本站三个平台开启自回复，回复他人与关键词过滤关闭。回复开关可分别开启或同时开启，均关闭时仅主帖；第三方查询负责回复类别筛选，本地解析、去重后保存，不重复按目标账号过滤，缺失目标账号不丢弃帖子。开启过滤后先按可编辑字面关键词初筛，再复用现有模型判断三类额度事件及后续消息。明确无关且不需复核的帖子保存 filtered_out，后台默认隐藏但可切换查看；明确人工保留或成为有效动作来源时解除过滤。reply_to 保存来源已提供的父帖 ID 和目标账号；上下文先复用本轮和已存材料，仍缺失时按明确 ID 付费补采，父帖不能替代外层动作依据。配置变化不重置成功截止、不回补历史或重筛已完成记录。

事件类型未明确细分时，在额度动作已有依据的前提下默认 direct_reset（额度重置）；只有明确重置卡或独立一次性奖励依据时才使用 reset_credit、bonus_credit。唯一可核验的后续帖优先沿用已有事件类型，默认或继承时 kindExplicit=false；不因类型未细分单独转复核。默认值不替代动作、对象与上下文核验，不将无关内容、普通限额提升或日常自动重置变成事件。

模型提出动作与引文，代码校验后接受；关联不明、事实冲突、资料不完整或证据不足转人工复核，不标记为无关隐藏。事件变化与待翻译任务、审计、通知变化在同一事务内登记。worker 按事实及编辑版本补齐七语言，旧任务不能覆盖新编辑；同版本翻译任务待复核不反复购买。无效响应在回执与任务状态提交前保持 received，持久化失败复用原响应；计费未知不自动重发。

正式业务只有事件、动作、帖子三张表，帖子与事件关系由动作来源推导。复核命令按 `events.create/update`、`actions.create/update`、`sources.add/remove` 和 `orders` 分组；每组表达明确操作，不用提交整份动作列表来暗示删改。事件及帖子关联弹框共用这些命令，新增对象以本次局部标识关联，浏览器用选择器操作；预览、版本核验与锁只涉及相关记录。

| 命令 | 表达的变更 |
| --- | --- |
| `events.create/update` | 创建事件及其类型、文案和范围，或明确更正事件范围；不写业务状态时间 |
| `actions.create/update` | 向选定事件添加动作，或更正现有动作的类型、文案和时间；更正影响该动作的所有来源 |
| `sources.add/remove` | 对选定动作补充或移除帖子来源；不修改动作事实、事件范围或 sequence |
| `orders` | 明确提交事件内动作次序；预览状态时间变化后才改 sequence |

同次提交可组合上述命令，相关记录版本及预览结果一并核验，涉及帖子文案、识别或保留操作的旧复核还须填写理由，关联及事件动作管理省略时自动记录操作说明，全部成功才提交。旧只绑定入口和依赖整个监控快照版本的复核方式不再保留。



当前版本仅支持已经转换完成的动作三表；原始旧库须先使用此前版本完成转换和备份，再升级当前版本。新安装仍运行完整历史迁移。当前格式的 v2 文案导入导出、离线重建和上下文修复使用现有版本、指纹、预览及审计流程；不保留运行时兼容或旧格式转换脚本。

`modules/reset-monitor/scripts/public-v2.ts` 核验工具仅导入导出展示文案及编辑版本，不允许直接写状态或业务时间；写入须预览、提供理由并核验版本，一次事务提交。真实数据放 `.data/local-preview/reset-monitor-v2/`，不提交快照或凭据。正式切换的停写、备份、迁移、转换与恢复步骤见[部署说明](deploy.md#动作模型与-v2-切换)。开发与测试只使用独立 `_test` / `_ci` 数据库和本地假服务，不自动执行真实模型、推送、迁移或公开部署。
