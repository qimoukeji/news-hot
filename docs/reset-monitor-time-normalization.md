# 额度事件时间写入规则

事件与动作的 `time` 必填，只保存 `instant`、`range`、`deadline`；不保存或公开 `date`、`unknown` 或 null。数据库和公开 API 使用同一份时间，读取接口不补时间、不转换旧格式。没有有效预告时 `announcedResetTime` 仍为 null；有预告时直接取当前有效预告动作的 time。

## 预告

- 原帖有准确时刻时优先采用，按来源时区解析后统一为 UTC。
- 只有日期或星期时，用现有日期定位规则确定日期，追加当天 18:00 UTC，保存 instant。
- 中文“本周／这周、下周、上周”按来源时区的日历周定位，不将“下周”解释为下一次遇到该星期。
- 只有截止日期时追加该日期 18:00 UTC，保存 deadline。“两天内”按发帖的 UTC 日期加两天后取 18:00；“48 小时内”按发帖时刻加 48 小时。
- 日期范围缺开始钟点时，开始日期在发帖 UTC 日期当天或之前就用发帖时刻，否则追加当天 08:00 UTC；缺结束钟点时追加结束日期 18:00 UTC。任一端有准确时刻就保留该端的准确时刻。
- 范围分隔符 `-`、`–`、`—` 与文字连接词共用同一规则。结束钟点早于开始钟点且原帖没有明确次日或结束日期时，视为倒置并进入待处理，不自动延至次日。
- 完全未提供时间时取发帖 UTC 日期 18:00；首次处理已经过该边界时取同日 23:59。处理时已跨日也不顺延，保存后重试或读取不重算。
- 同一预告随后补充或更正具体时刻时覆盖原预告动作 time，保留动作 ID、顺序、已有文案及来源。分批或同组识别均可覆盖。仅重述日期不覆盖已有具体时刻；不同轮次分开。旧预告对应的自动推定失效，官方确认及人工核对不受影响。

## 确认及其他动作

有来源的官方 confirm 使用确认原帖发布时间，保存 instant，不从时间引文复用预告或猜实际时刻。无来源人工确认保留管理员填写时刻，自动确认保存预告边界（instant/deadline 的 at，range 的 through）。

管理员通过新增或编辑动作核实已有自动确认时，保留动作 ID，并持久记录其人工核实身份；后续修改原预告不得将该确认当作自动推定作废。该身份仅供内部归并和审计，不进入公开契约。

progress、amend 和取消有可用明确时刻、范围或截止时照存；只有日期或没有时间时沿用各自缺省：progress 用发帖时刻，amend 用不早于发帖时刻的最近一个 10:00 UTC。

## 解析异常与复核

时间引文无效、日历非法、时区不支持、区间倒置或解析抛异常，均不能阻止已有明确事实的事件和动作生成。使用发帖 UTC 日期 18:00 的 instant，并在同一事务通过现有 needs_attention/review_reason 流程保留时间问题。不因时间问题另建一条脱离原事件的动作，不自动重买识别响应；自动推定仍受待处理来源阻断。确认始终直接使用合法的来源发布时间，不需要解析完成时间引文。

## 契约、存量和验证

三平台、后台表单、v2、Webhook、Agent、MCP、OpenAPI、样例及 when-reset 消费校验同步收紧。只修改 when-reset 代码，不发布该项目。统计、预测和通知仍使用已保存的时间。

存量 date、null 及有来源确认的非发布时间先只读盘点；按动作生成转换预览，停写、验证完整备份并在授权后应用。保留事件、动作、来源、付费回执、审计及既有通知修订号。受影响的历史预告若已到期且符合推定条件，在切换事务内静默保存确认，再重建通知比较基线。当前 scope 切换与时间切换完成后才允许新服务启动，不维护运行时旧格式转换。已保存的无来源精确确认不因新规则批量改写。

静默确认覆盖范围变化或时间变化涉及的事件，包含停写期间到期的原本有效预告。没有动作的已审核草稿可将资格保留在事件摘要中完成切换，继续保持草稿，不为通过校验捏造动作。离线快照中的集合必须完整序列化并恢复，预览与应用使用同一值。

日常实现只跑相关测试和类型检查；完整验证按根目录 AGENTS.md，在明确推送或部署审查时执行。
