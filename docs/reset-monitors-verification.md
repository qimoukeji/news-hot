# 额度监控验证

三个监控的账号、套餐、默认产品和作者时间策略由 `site/reset-monitors.ts` 配置。公开定义与后端定义读取同一配置，采集、识别、关联、人工复核和展示共用 `modules/reset-monitor/`，统一只采非回复主帖。

## 行为覆盖

- 多账号完整分页、帖子 ID 去重、任一账号或后续处理失败不推进整轮成功检查点。
- 查询排除回复，入库再次排除回复、自回复、纯转推、错误作者和窗口外帖子；保留外层非回复引用帖，只使用随响应附带的引用正文，不请求父帖或其他上下文。
- 新增或重新添加账号的起点在请求前保存，失败后不漂移；显示名或大小写变化不改变起点。旧账号仍补齐失败窗口，新增账号不补采此前历史。
- 没有历史初始化、关键词回复筛选、每日查漏或旧处理模式；三平台执行同一增量、识别、关联与 v2 补全流程。
- 采集覆盖记录与成功检查点按提供商隔离；新提供商首次运行保存当前起点，尚未写成功检查点即失败时重试沿该起点继续。切回原提供商仍补齐其原范围的未完成窗口，公开覆盖说明读取当前提供商的记录。
- 历史清理保留全部事件（含撤回）、关联及直接和间接证据；预览不写库，应用绑定指纹，发生并发修改即拒绝。事件及关联内容、三个平台公开 v2 事件投影保持一致。
- 首次主帖流程发布在缺少清理批准时拒绝停站；旧 API/worker/web 停止并验证备份后清理，只启动新 API/web 验证。清理开始后失败不自动回旧版；普通发布及失败恢复不自行启动原已停止的 worker。
- 三种事件全部启用；Codex 奖励可以入库、复核和展示，Claude 一次性云会话奖励边界保留。混合消息逐命题判断，奖励不计入重置次数，不使用账户回执确认活动。
- 只有显式绑定 Tibo 策略的作者允许预测；其他账号缺时间保留原话，奖励开放、领取截止和到期一律不预测。事件投影使用自身时间策略，历史记录不回填。
- 事件保存当前时间依据的作者，跨账号更正时间后人工修改范围保留完整预测，人工修改时间使用提供该时间的作者策略；帖子复核重算时读取原帖实际作者。
- 产品、套餐和额度周期冲突不误合并；明确更正可修订套餐范围。跨账号必须有可核验的上下文或原帖链接，仅模型事件 ID 和时间相近不能证明同一事件。
- 页面、API、Agent 和 MCP 展示实际作者与账号覆盖起点。模型原结果及人工审计保留。
- 日历使用“官方已确认”表达原帖确认，最新补充说明的作者不能成为确认人；确认时间与原帖卡作者分别展示。
- “人工复核完成”只由 `manualReview.completed === true` 表示；未完成记录继续显示需复核。后台列表的 `needs_review`、“需复核”筛选与公开待复核计数共用同一条件。
