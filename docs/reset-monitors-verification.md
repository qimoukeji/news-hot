# 额度监控验证

三个监控的账号、显示名、默认产品、套餐和 v2 目录由 `site/reset-monitors.ts` 配置。采集、识别、动作、人工复核和公开投影共用 `modules/reset-monitor/`；验证必须覆盖 Codex、Claude、Grok，不能只用一个产品证明共享行为。

## 执行方式

从待处理帖子新建事件并关联有效首个动作，三平台均须验证：预览显示处理状态转 processed、原因清空且不写入；提交将事件、动作、来源与帖子完成状态一并保存，旧原因留审计，版本冲突或取消不留下任何部分更新。仅给已有动作补来源、动作更正或移除来源仍保留原识别进度；新事件引用其他帖子时不能误完成当前帖。仅有中文“所有用户”等固定范围标签的事件，在模型关闭时也可通过纯展示补译公开，scope.type 和代码、数据库保存值均不变；自定义资格条件、冲突文案及 selected_users 的不完整范围仍禁止公开。

自动识别回归须覆盖三平台：相邻问句与 your 不误拦明确完成句，未来、否定、个人感受及无关事项的完成不能确认额度事件；下一小时、within/over、EOD 保留区间与来源时区，模糊几分钟不补造钟点。父帖和引用链逐级校验身份、时间与循环，唯一对象可继承原范围，多候选即使模型填写事件 ID 仍需复核；取消、撤回不得误当新事件。一个事实无效不阻止其他独立事实入库，已关联但待处理原因保留，回执事务提交，重复或过期任务不写第二次，不同类型不能共用同帖分组。目录不完整时动作保留，unknown 标签、空代码数组、摘要限制在页面、API、Agent、MCP 与 Webhook 一致，普通补来源不得覆盖已有范围。

人工创建闭环须覆盖三平台：列表顶部入口、创建与编辑共用弹框、取消与失败保留输入、创建后在事件列表可见且无动作；无动作时公开接口、统计和 Webhook 均无变化；在列表添加首次有效动作后公开并产生一次 created，含草稿先经历基线初始化或翻译的情况。手机布局、初始动作限制、版本冲突和后续事件编辑仍须正常。

帖子列表须覆盖三平台的紧凑卡片、仅编辑和创建入口、作者及识别说明只读显示；创建弹框填写真实来源与发布时间，同链接或同帖 ID 不覆盖旧数据；编辑仅标题摘要且保留识别状态、原文、回执和动作关系。验证行版本冲突、读取重试、失败保留输入、取消不写入、手机滚动和焦点；人工创建无采集、识别、动作、事件或通知副作用，原文不得进入审计和公开出口。创建历史帖子后按其北京时间日期定位列表。

使用 Node.js 24 及独立 `_test` / `_ci` 数据库。数据库账号需要建库权限，测试框架为每个数据库测试文件创建独立副本。全部外部请求只连本地假服务，测试不能使用运营快照、生产凭据或真实采集、模型、推送。

```bash
npm run typecheck
DATABASE_URL=postgres://127.0.0.1:5432/monitor_test npm test
npm run test:standalone
npm run build -w @aihot/web
node --test apps/web/tests/*.test.ts
node scripts/smoke.ts --base http://localhost:3000
```

PowerShell 设置测试连接使用 `$env:DATABASE_URL='postgres://127.0.0.1:5432/monitor_test'`，然后执行对应命令。smoke 前启动本地 API/web，保持采集、模型和所有推送安全阀关闭。数据库转换集成测试需要与服务器兼容的 `pg_dump`、`pg_restore`，可通过当前测试进程的 PATH 提供便携客户端，不修改系统配置。

OpenAPI 由 `node modules/reset-monitor/scripts/openapi.ts` 生成到 `site/public/openapi-v2.json`。检查生成结果与共享契约一致且重复生成没有差异；`openapi-v1.json` 只移除额度监控路径及无人引用的专属 schema，新闻接口继续可用。

## When Reset 接口联调

When Reset 的消费契约以本仓库当前 `modules/reset-monitor/public-v2.ts`、`webhooks.ts` 与 [v2 规范](reset-monitor-v2.md)、[Webhook 规范](reset-monitor-webhooks.md)为准。载荷 `schemaVersion=2`，签名头仍为 `v1=`；三类事件共用四动作和四状态。消费端须接受动作标题、业务时间、`invalidatesEvent` 和完整 `sources[{postId,sourceId,url}]`，仅确认允许空来源；预告时间与最近有效确认时间可并存，不保留单来源、奖励旧状态或旧 Webhook 载荷兼容分支。

两个仓库位于同一父目录时，从 `when-reset/` 运行：

```powershell
npm run test:news-hot -- --news-hot ../news-hot
```

该命令直接导入本仓库的动作投影、查询、分页、ETag 和签名代码，用三平台合成动作及随机端口本地 HTTP 验证 when-reset 的真实客户端与回调处理器。覆盖多来源、无来源确认、后续官方补证保留动作 ID、统一 completed、并存总览时间、预测日期、IANA 时区、纯日期与区间、分页游标、304、重复及旧修订去重、平台缓存失效与撤回恢复。数据库、队列、凭据读取及外部服务入口在验收进程隔离；不加载 `.env`，不连接运营数据库或发送真实通知。

页面验收由 when-reset 的 `tests/e2e/news-hot-actions.spec.ts` 与 `site.spec.ts` 检查七语言、浅深主题、桌面和手机。多来源动作显示全部原帖；无来源确认保留核实或推定文案且不补造链接；业务时间与发布时间分别展示，纯日期不补时钟，取消修订与普通修订可区分。

四类通用动作须分别验证：announce、confirm、progress、amend。三类事件共用 announced、in_progress、completed、cancelled；有效 confirm 统一为 completed，关闭、到期、重开使用 progress。取消只能通过 amend 的 invalidatesEvent=true 进入 cancelled，保留历史但退出预告、最近确认、次数和间隔统计；普通修订不覆盖有效官方确认，修改摘要不得改变状态。业务取消为终态，新增动作不能恢复；更正或删除错误取消动作后才重算。新预告和明确计划变化对无来源确认的失效规则单独验证，不能按文案推断。历史 restore 动作须在受控转换中列明、清理并审计，验证删除后回到 cancelled 的事件影响；管理撤回恢复及 Webhook restored 仍正常保留。事件范围由单独的事件命令明确更新，不放入动作草稿，不随旧动作回放或删动作猜测；给已有动作补来源不能改范围或 sequence，官方补证可明确升级同一无来源确认的文案与时间。去重不靠文案哈希，只有当前无来源确认允许按事件升级，同类官方事实不能泛化合并。后台以事件为动作管理入口，帖子复核通过选择器操作，不手写对象 ID。

总览单独验证：三类事件均参与最近 90 天精确确认间隔中位数；至少两个时间点且存在正间隔才有 typicalInterval。新事件预告不清空其他事件已有 resetTime；同一事件新预告可使旧无来源确认失效，有效官方确认不受普通进展或修订覆盖。预测等于 resetTime 加间隔；北京时间当日预测保留，早于今天才显示今天，跨 UTC/北京时间日期边界、纯日期和区间均须验证。

## 转换演练

在独立测试库构造带复合关联的旧表和模拟付费回执，使用真实 `pg_dump -Fc` 生成完整备份，再调用转换工具。必须验证：

- 预览只读且不输出原文；指纹包含会影响转换的全部输入，输入变化拒绝应用。
- 不完整、截断或不可读取的备份、活跃 worker、缺失关联、歧义事实及无法安全转换的明确范围或时间均阻止应用。
- 分阶段升级分别演练：分离动作来源先转换并限定清理到 0115；relations prepare、预览、apply 后 cleanup 仅到 0122；post-processing prepare 到 0124，预览并 apply 后才运行剩余 0125–0126。原始旧三表且新业务表为空可先全迁移，再直接转换到最终三表及四状态。不得跨过批量转换直接全量迁移已有数据。
- accepted、unrelated 均转 processed，needs_review 转 needs_attention；旧 manual=true 的 pending 转 needs_attention，原因保留／追加且特殊清单可核对，pending、failed 和待处理不能因 manual 被提升为已处理。旧来源与关系阶段不得把新状态写进尚未替换的旧 CHECK。
- 核验帖子、事件、动作、内嵌来源数量及逐事件 sequence；遗留只绑定记录单独列明并转帖子复核，不伪造动作或保留正式绑定。来源依据决定状态，不把账户核对转换为官方确认。
- 正文恢复逐条核对 monitor_id、帖子 ID、作者、发布时间、已保存 URL 和来源指纹；仅用既有回执或旧快照。原文缺失、元数据冲突、多引用候选时阻止应用，不重新采集或调用模型，quote-map 的人工选择须能证明是该外层帖子的直接引用。
- 删除回执核对专属审计，清除其他监控快照中的原文和该功能内容，保留内部付费响应、无关人工记录及新闻模块审计。
- 旧通知待发内容清除，已有送达记录保留；WebHook 修订号不碰撞，历史比较基线和飞书截止阻止重发；成功截止和账号起点不漂移。
- 未转换旧记录时新代码拒绝运行；转换失败事务回滚，正式恢复按[部署说明](deploy.md#动作模型与-v2-切换)停写并从完整备份恢复。

## 真实样本核验

识别和时间规则变更使用一批公开真实帖子对照修改前后结果，记录样本来源、有效日期、变化数量及逐项判断理由；主帖、本人回复、自回复、引用帖、同帖多动作、发卡提醒、奖励细则、明确时区和跨年日期都应覆盖。只读样本及报告放 `.data/local-preview/`，不提交运营数据；没有明确授权时不调用外部模型或供应商。

模型分类一致率不是人工准确率，离线规则回放也不证明真实供应商召回率。验收分别检查遗漏、错误事件数、错误关联、状态、范围、时间与复核量；不能仅凭通过测试或模型 schema 合法宣称业务识别准确。
