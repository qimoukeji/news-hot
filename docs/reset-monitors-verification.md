# 额度监控验证

三个监控的账号、套餐、默认产品、作者时间策略与可选采集筛选由 `site/reset-monitors.ts` 配置。初始名单没有新增账号；公开定义与后端定义读取同一配置，采集、识别、关联、人工复核和展示共用 `modules/reset-monitor/`。

## 行为覆盖

- 多账号完整分页、帖子 ID 去重、任一账号或后续处理失败不推进整轮成功检查点。
- 新增或重新添加账号的起点在请求前保存，失败后不漂移；显示名或大小写变化不改变起点。旧账号仍补齐失败窗口，新增账号和新筛选范围不自动补采此前历史。
- 未完成初始化的原查询、版本及游标保持不变；不匹配配置在付费前报错，原追加查询机制继续可用。
- 采集覆盖记录与成功检查点按提供商隔离；切换提供商并初始化后，切回原提供商仍补齐其原范围的未完成窗口，公开覆盖说明读取当前提供商的记录。
- 三种事件全部启用；Codex 奖励可以入库、复核和展示，Claude 一次性云会话奖励边界保留。混合消息逐命题判断，奖励不计入重置次数，不使用账户回执确认活动。
- 只有显式绑定 Tibo 策略的作者允许预测；其他账号缺时间保留原话，奖励开放、领取截止和到期一律不预测。事件投影使用自身时间策略，历史记录不回填。
- 事件保存当前时间依据的作者，跨账号更正时间后人工修改范围保留完整预测，人工修改时间使用提供该时间的作者策略；帖子复核重算时读取原帖实际作者。
- 产品、套餐和额度周期冲突不误合并；明确更正可修订套餐范围。跨账号必须有可核验的上下文或原帖链接，仅模型事件 ID 和时间相近不能证明同一事件。
- 页面、API、Agent 和 MCP 展示实际作者与账号覆盖起点。模型原结果及人工审计保留。
- 日历使用“官方已确认”表达原帖确认，最新补充说明的作者不能成为确认人；确认时间与原帖卡作者分别展示。
- “人工复核完成”只由 `manualReview.completed === true` 表示；未完成记录继续显示需复核。后台列表的 `needs_review`、“需复核”筛选与公开待复核计数共用同一条件。

数据库验证使用临时源码副本与独立 `review_fixes_test` 数据库。付费服务测试仅连接本地假服务；本地 smoke 关闭采集、模型及推送安全阀。没有修改生产数据库、凭据、环境文件或部署配置，没有执行真实采集、模型调用、推送或历史补采。

验证日志在 `.data/local-preview/review-fixes/`：`typecheck.log`、`focused.log`、`database.log`、`standalone.log`、`build.log`、`monitor-web.log`、`web-all.log` 与 `smoke.log`。Windows WebKit 的 HEAD 对照日志为 `.data/local-preview/ui-head-baseline-tests.log`。

## 已保存实帖对照

对照对象是已保存原帖及既有模型结果或离线人工命题，没有重新调用模型，也没有写回运营数据。

| 监控 | 保存原帖 | 有命题的帖子 | 对照命题 | 排除／保留判断变化 |
| --- | ---: | ---: | ---: | ---: |
| Codex | 1,183 | 70 | 72 | 0 |
| Claude | 209 | 11 | 12 | 0 |
| Grok | 2,928 | 17 | 17 | 0 |

Codex 原帖 `2095651088502591861` 同时给出按日补偿规则和首张卡约三小时后发放的明确动作。公共校验保留首张卡事件，不能仅凭 `every day` 将它误删为日常自动重置；只有每日规则、没有具体首张发放证据的命题仍排除。该真实例子已加入回归测试。

Claude 的 API／云会话消费池边界与原规则一致。对缺少可核验关联的命题不补造线程依据。Grok 的 2,928 条保存原帖还用于筛选对照：接受结果变化为 0，原查询、追加查询及 v3 版本逐字一致。

这些结果验证公共确定性规则和保存命题的处理边界，不代表新提示词的线上模型准确率或真实供应商搜索召回率。离线明细为 `.data/local-preview/unify-verification/offline-results.json` 与 `offline-filter.json`。
