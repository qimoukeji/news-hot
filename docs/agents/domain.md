# Domain Docs

本仓库采用 single-context：共享领域用语集中在根目录 `CONTEXT.md`。虽然使用 npm workspaces，当前 Codex、Claude、Grok 监控共用同一套帖子、动作、事件模型，按现有文档统一阅读即可。

## 阅读顺序

1. 先读根目录 `AGENTS.md` 和 `README.md`。
2. 领域用语读取根目录 `CONTEXT.md`；保留现有文件名，不创建重复的 `GLOSSARY.md` 或领域映射文件。
3. 进入模块前读取该模块的 `AGENTS.md`、README 和本次任务对应的 `docs/` 文档。
4. 如存在 `docs/adr/`，读取涉及当前工作的 ADR。当前缺少 ADR 目录不是阻塞条件，不为初始化创建空目录或虚构历史决定。

## 文件用途

- `CONTEXT.md`：领域概念、边界和规范用语，不作为临时计划或执行日志。
- `docs/adr/NNNN-short-name.md`：需要保存的架构决策，只有实际形成决定时才创建。按现有 domain-modeling 技能的 ADR 格式记录，不追溯编造。
- `docs/agents/`：跨工程技能复用的仓库配置，只保存任务跟踪和领域文档消费规则，不复制业务规格。
- 业务规格、部署和运行约定继续使用仓库既有 `docs/`；临时验证与私有运营材料继续放 Git 忽略的 `.data/`。

## 统一用语和决定

输出需求、审查、测试或实现建议时使用 `CONTEXT.md` 的术语；已明确禁止的同义词不作为替代。发现文档与代码不一致时，先说明具体冲突，不悄悄改写领域定义。

遇到与 ADR 冲突的方案时，指出对应文件与取舍。修改业务文档或规则须遵循根目录和模块 AGENTS.md；本配置不授予 push、公开发布、凭据修改或数据库迁移权限。
