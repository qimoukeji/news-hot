# 额度监控模型接入与类型校验

额度监控使用现有 `monitor` 模型能力及统一的生成式识别流程，不接入 TypeSafe AI，不维护旁路过滤器或第二套判断流程。模型必须同时提供动作候选、结构化事实与七语言标题摘要；只有类型合法不足以接受事实，仍需校验来源、时间、范围和事件归属。

## 输入和存储边界

采集把原文 `text` 及必要的单层随帖引用 `quoted_post` 写入帖子，运行识别、引文和时间核验直接读取帖子，不读取采集回执正文。原文与引用分开，引用不能代替外层帖子的动作依据。帖子还保留来源、作者、发布时间、链接及七语言标题摘要，不存全文翻译；事件、动作、公开响应和业务审计不复制原文。供应商原始请求响应仅存内部付费回执，供计费与请求续处理。

平台 collection 独立控制回复采集与关键词加模型过滤，默认关闭。回复的 reply_to 保存已提供目标，本地不因目标账号缺失过滤；父帖与引用先复用本轮及已存材料，缺失时按明确 ID 付费补采。按真实关系组织一组一次识别，每项动作仍核验所属原帖证据；补齐后仍有歧义转人工。过滤复用同一次识别调用的相关性结果，不能因没有动作就判无关；明确无关且无复核问题时保存 filtered_out，识别失败与待复核不隐藏。后台显式 keepPost 或有效动作补来源解除过滤，文案编辑不改变过滤结果。

一个帖子可支持多个动作，一个动作可有多个帖子来源。输出不能用帖级单一状态代替动作列表，也不能仅凭类型相同合并不同事实；相同事实应复用动作并补充来源。关联不唯一、证据不足或与既有事实冲突时转人工复核，不猜测目标。

帖子识别进度仅为 pending、processed、needs_attention、failed，保留 review_reason，不用 manual 或 accepted/unrelated 表示是否支持动作。worker 只识别 pending，接受事实、转人工或记录失败前都核验输入原始版本和当前 pending 状态；过期响应不能覆盖人工操作。成功识别无论有没有动作都设 processed，动作管理不改变处理状态，翻译任务不改识别进度。

## 接受模型结果的条件

- 动作类型只接受 `announce`、`confirm`、`progress`、`amend`、`restore`；新事件必须从预告或确认建立。三类事件共用 announced、in_progress、completed、cancelled 状态，confirm 均为 completed。正式关系只有事件包含动作、动作引用帖子；每项事实须由当前监控的有效来源支持，不另存帖子事件绑定。
- 关闭领取、到期、重开作为 progress；取消使用 amend 并设 invalidatesEvent=true，失效事件保留历史但退出总览时间和统计，restore 只恢复预告。普通 amend 只改事实，不从摘要或额外 result 字段推断状态。影响范围只存事件，事件创建或范围更新与动作、来源、顺序命令分开表达；动作草稿不包含 type 或 eventScope，不保存 scope、result 或文案哈希。
- 动作 `sources` 只存 postId，事件内 `sequence` 决定事实重放顺序。补来源不改变顺序或已有事实；重排须明确提交，不能因找到更早来源而自动重排。后台选择事件、动作和来源，不要求手写 ID；版本核验只涉及本次关联记录。
- 标题摘要仅描述已接受的业务事实，七语言齐全；不复制全文，不把原文引文、模型理由或内部依据写进公开文案。
- 明确产品、套餐、用户条件和额度窗口受代码约束，补全不得扩大或替换范围，无法映射目录则转复核。
- 时间由统一来源解析器及 Temporal 处理，保留日期和区间精度，不使用作者习惯或模型预测。PST 固定 UTC−08:00，PT 使用 America/Los_Angeles 夏令时规则。
- 模型不能直接修改事件状态、首次发布时间或总览统计。状态和业务时间只由有效动作推导，人工文案核验也不能直接写状态时间。
- 付费请求使用稳定输入身份、预算及回执；先持久化响应再校验，写入中断复用 received 响应，计费未知不自动重发；无效结果转复核，相同版本不重复购买。

## 修改或新增服务前的证据

先证明现有流程的具体错误及新增服务能解决的问题，再以公开真实样本比较遗漏、误报、错误关联、时间范围错误、复核量、总费用与延迟。候选选择、字段核验和生成式抽取是不同能力，不能仅因服务支持类型化输出就假定可以直接替换当前识别器。

任何新付费适配都必须经过现有预算、安全阀和回执，禁止 SDK 隐藏重试或绕过预算。验证只连接本地假服务；真实付费评测、凭据修改和生产上线分别按授权执行。共享契约见[公共额度接口 v2](reset-monitor-v2.md)，验收场景见[额度监控验证](reset-monitors-verification.md)。
