# 额度动态影响范围简化

适用项目：`news-hot` 和 `when-reset`。本文定义两仓字段与切换要求；接口细节见 [v2 接口](reset-monitor-v2.md)和 [Webhook 协议](reset-monitor-webhooks.md)。

## 事实与识别

产品、套餐、额度周期和具体资格只写入已有的七语言事件摘要和动作摘要，不设独立的名称数组、代码或目录。新产品、新套餐或新周期不需要先录入配置。原帖有明确限制就照实写，没提就不补，不凭平台、作者、常识或定价页推断。

识别模型直接输出摘要。提示词用一条规则说明：写清原帖明确适用的对象、条件和例外，区分这些条件分别对应哪个动作。例如「重置了每周额度，同时提高五小时上限」只能把每周额度写成已重置；「五小时额度」也不能当作发放时间或个人账户倒计时。

- 删除三平台的产品、套餐、额度周期目录、代码、别名、产品和套餐冲突表、作者默认产品，以及相关识别输入、独立输出字段、映射和校验。平台标识、官方账号和采集规则保留。
- 模型结合原帖、回复、引用及已有事件判断是否同一活动。证据不足时不自动合并；普通补来源不得改写已有动作的范围，明确变化通过有来源的新动作表达。
- 保留现有的来源、动作类型、业务时间和保存版本校验。确认、预告、预测、历史间隔统计、个人计时、付费回执和模型调用位置保持现有规则。读接口和页面不调用模型。

## 数据、接口与页面

| 位置 | 目标 |
| --- | --- |
| 事件 `scope` | 只保留 `type` 和 `note`，表达简短的用户范围说明；`unknown` 表示未核实，不能当作覆盖所有用户。删除 `productCodes`、`planCodes`、`quotaWindowCodes`。 |
| v2 总览 | 删除 `platforms[].catalog` 整体，不返回空目录或替代字段。平台、来源、预告、时间和统计字段不变。 |
| v2 事件、Webhook、Agent、MCP | 共用同一份事件结果；产品、套餐和周期只读摘要，不再查表、补默认值或按代码筛选。Webhook 保留路径、`schemaVersion: 2`、签名、去重和事件修订语义。 |
| `news-hot` | 更新识别、保存、公开投影、后台、OpenAPI、文档和测试。删除退出使用的配置与业务状态，不保留运行时兼容层。 |
| `when-reset` | 同步更新总览、事件列表和签名回调的严格校验，移除目录引用检查及展示映射。历史记录展开时显示摘要，让读者能看到实际资格；事件摘要缺失时，动作摘要仍随对应动作展示，不把旧动作的资格当成当前范围。邮件和 Telegram 沿用已有摘要来源。更新 OpenAPI、示例和测试。 |

## 历史数据与切换

1. **先只读盘点。** 找出只在旧代码里保留产品、套餐或周期的记录，核对既有摘要和原帖；已写清楚的摘要不动。缺失的事实补入对应动作的完整七语言摘要，不能仅补事件摘要。有来源事件的资格必须保存在有来源动作中，保证后续事件概述仍能读取；只有无来源确认的事件可保留在经核对的确认摘要中，不补造来源，也不作为官方事实送模型。有歧义的列给人工确认，不靠旧目录推断完整资格，不重跑历史识别。核对已保存的旧格式待发 Webhook、在途识别组、尚未进入旧基线的真实变化和接收方。
2. **先联调，再切换。** 两仓用三平台本地合成数据完成联调。现有 v2 路径和 Webhook 版本号保留，但删必填字段是不兼容变更；安排在同一个发布窗口切换，不能单独先上线其中一仓，也不长期并行维护两套格式。
3. **处理旧状态。** 优先用旧契约处理待发 Webhook、让旧 worker 保存已经收到的识别结果。剩余未完成项先核对，不能直接丢弃或按新载荷重发。经批准后清理事件范围 JSON 的旧字段，保留事件、动作、来源、回执和已发记录；按新投影重建 Webhook 比较基线，保留既有修订号，不因删字段或补历史文案触发通知。业务数据写入、通知操作、推送和部署单独按授权执行。

## 验收

- 用目录里从未出现的新产品、新套餐或新周期验证：有明确原帖就能正常形成事件，摘要保留实际限制；比较、排除和未提及的信息不会被写成适用资格。
- 验证补来源不会改写已接受范围；「重置每周额度、提高五小时上限」不会变成两项重置；自动确认、统计、预测及个人计时继续使用现有口径。
- 在 `when-reset` 运行 `npm run test:news-hot`，覆盖三平台总览、历史、日期与分页、签名回调、缓存失效和重复回调；再核对七语言历史详情及邮件、Telegram 里的摘要。同步校验两仓 OpenAPI 和示例。
- 用含旧事件和待发记录的隔离数据演练：旧资格在摘要可读，字段精简本身不生成 `updated` 或补发历史通知。验收使用本地合成数据和假通知，不连接业务库或发送真实通知。
