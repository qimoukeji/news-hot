# news-hot 部署约定

- 这里仅存本站的部署配置、脚本、测试和操作说明，不修改行业规则或共享业务逻辑。
- 所有修改在 `dev/codex` 完成。部署前更新远端引用并核验开发工作区无待提交变更、本地开发分支与 `origin/dev/codex` 完全一致；有未推送提交或无法核验时禁止部署。仅在使用者要求部署时将开发分支合并到 `codex/deploy`，再推送部署分支发布，完成后回到开发分支。不在部署分支直接修改或绕过开发分支推送。
- `compose.yml` 使用独立项目 `news-hot`，只能监听本机端口；公开域名通过宝塔 Nginx 接入。
- 服务器目录固定为 `/opt/news-hot/`：`releases/<完整 SHA>` 存不可变发布包，`shared/` 存私有配置和发布状态，`backups/` 存数据库及附件备份，`current` 指向已验收版本。
- 密钥、`.env`、数据库、附件和执行日志不进 Git 或 Actions artifacts。开发验证及待审批文件放在仓库忽略的 `.data/deployment-*`。
- 不自动删除数据库、备份或 Docker 卷。上传临时包验收后可以删除；历史版本与镜像仅按 README 中明确的清理命令处理。
- 普通发布不执行未批准的迁移。批准绑定到提交、已发布版本及迁移文件哈希；批准后重新检查，条件变化则停止。
- 每次发布使用同一把服务器锁，worker 正常退出后才能备份及迁移。迁移开始后失败必须保持应用停止，不能自动接回旧代码。
- 非回复主帖流程首次升级须绑定只读历史清理清单的指纹并单独批准；未获批准不得停止现有应用。停止旧 API、worker、web 并验证备份后，才以新镜像清理；开始清理后失败保持应用停止，不自动接回旧代码。清理发布只启动 API/web，worker 由运营单独恢复；普通发布与失败恢复也不得自行启动发布前已停止的 worker。
- 脚本适配服务器 Bash 4、Docker Compose 2.27；不用需要升级宿主系统的功能。新行为须用假的 Docker/HTTP 服务验证失败路径。
- 首次配置、密钥安装、CI/CD 修改、push、业务数据导入和公开上线遵循用户的审批要求；先准备具体可审阅结果。
